## 七条最强判断

### 1. 竞争叙事需要收窄：记忆、引用、模板和自动交付已在主流产品覆盖范围内

**事实，VERIFIED。** AlphaSense SuperAnalyst 的 2026-08-05 官方文档明确写项目历史、指令、分析方法跨会话保留，支持团队自定义 Skills，以及报告、模型和其他交付物的生成和更新；文档同时说明当前 beta。Hebbia 官方 2026-03 更新写共享 Projects、定时 Agent、跨来源实体归一和 Excel 输出。Bloomberg 官方 ASKB 页面写其当前 beta，提供出处引用、底层 BQL 计算代码以及可保存、调度和在机构内分享的工作流。[AlphaSense 文档](https://help.alpha-sense.com/hc/en-us/articles/53909448564243-Getting-Started-with-SuperAnalyst)、[Hebbia 更新](https://www.hebbia.com/blog/the-disclosure-march-2026)、[Bloomberg AI](https://professional.bloomberg.com/products/bloomberg-terminal/ai)

**[推断]** BP「Agent 有模型没有框架」「大厂做校准必然伤害其生意」过于绝对。具有订阅与企业工作流收入的产品，并不必然依赖刺激交易。更稳的竞争问题是：同一份历史证据能否按当时可见状态重放，能否冻结事前判断，能否定位失效原因，能否把候选经验放到未看过的数据中验证。应把这些能力组合做成实际对照任务，不能靠产品口号推导独占性。

**与 BP 的关系：** 既有 spec 已有这条方向；新增的是现时竞争反证。框架资产可能有用，但「唯一不可复制」也要改成可检验命题：能否提取为他人持续愿用的工作法、换创始人后能否交付、效果能否复验。

### 2. 值得优先验证的痛点是“旧判断没人维护”，可把回检变成持续判断维护

**事实，VERIFIED。** Hebbia 把跨公司信号关联、管理层叙事变化、内部研究再利用和持续监测列为投资团队工作流；AlphaSense 也描述以新资料更新已有交付物。[Hebbia 投研用例](https://www.hebbia.com/blog/how-hedge-funds-use-hebbia)、[AlphaSense 文档](https://help.alpha-sense.com/hc/en-us/articles/53909448564243-Getting-Started-with-SuperAnalyst)

**[推断]** 时间长河可以将“最新发生什么”推进为“我以前哪条判断现在必须重审”。建议验证的具体产物是一页变更单：新增证据 → 影响哪些旧主张 → 哪个升级/放弃条件触发 → 哪些还无法验证。再加用户有限研究时间的排序：先处理最可能改变已登记判断的事项。这样卖的是持续覆盖与少漏重要变化，不是更多消息。

**与 BP 的关系：** BP 已有观察条件和定期回检；新增是按依赖关系传播变化、处理未完成核验与逾期判断，以及将它独立包装为每日可验收服务。可称“研究待办积压”，不需要为此另造一个平台。

**验证：** 拿用户自己过去一周的几条判断，比较原流程与变更单；记录重要变化漏检、误报、完成复核时间，以及用户是否在下一周主动回来。公司官网能证明有此类竞争场景，不能证明本产品能抓住需求。

### 3. 机构入口需要一个可重复交付的工作单元，而不只是泛泛的 FDE

**事实，VERIFIED。** AlphaSense 官方定价说明按年度订阅，可按席位或企业组织购买；企业方案包含内部资料、IT/专业服务及私有云选项。Hebbia Projects 的设计是让团队在同一交易项目空间共享上下文，其定价页导向 Demo，没有公开可核验的统一金额。[AlphaSense 定价](https://www.alpha-sense.com/pricing/)、[Hebbia 更新](https://www.hebbia.com/blog/the-disclosure-march-2026)、[Hebbia 定价](https://www.hebbia.com/pricing/)

**[推断]** 可从小型研究团队的“周会证据包与判断交接”切入：冻结会前资料；各人的不同假设与负责人留痕；新同事能回到原始依据；会后有明确复核日期。购买方可能是研究负责人，使用方可能是分析师，价值在于节约交接和复核工时、降低关键人离开造成的知识丢失。预算来源、采购流程和痛感需访谈，不推定机构必然高价买单。

**与 BP 的关系：** 面向投教机构和研究团队的 FDE 已有；新提出的是首个可售单元与扩张方式。先只承接同一个流程，接着向同一客户的第二个团队扩展，才有复用证据。定制费可覆盖导入，但要分别记一次性服务与持续软件收入；每单都换系统、换规则、创始人亲自陪跑，会形成咨询生意而非可复制产品。

### 4. 决策回检还可能服务“评价研究过程的人”，这是已有品类，可研究本地细分入口

**事实，VERIFIED。** Essentia 官方将经理与研究员、首席投资官/监督团队、资金配置者/基金买方列为不同服务对象，围绕决策归因、行为变化与经理能力比较提供服务。本轮只核验其产品定位，未核验宣传中的收益效果或统计有效性。[Essentia Insight](https://www.essentia-analytics.com/product/essentia-insight-allocator/)

**[推断]** 用户判断轨若以后达到足够长、够完整、归因严谨的记录，可支持团队复盘、研究人才培养、框架适用条件审查，而不是只帮助当事人回答问题。长期可能的购买方包括投研负责人、投教交付负责人；更远的经理评估与资金配置要额外能力与专业边界，不能从观察剧本直接跨过去。

**与 BP 的关系：** BP 的“高手认知复利”是个人层；新增是谁会为他人的研究过程质量付费。但这并非无人做。也要防止经理把“被评价”视为监督工具而拒绝记录：个人复盘默认私有，团队聚合可见范围另定；不能把愿意自我反思等同愿意向老板暴露每个念头。

### 5. 个人数据飞轮不自动产生跨用户网络效应，隐私承诺可能就是购买条件

**事实，VERIFIED。** Hebbia 官方安全页面承诺客户资料/提示/输出不用于其或模型供应商训练，不同客户环境隔离，并提供数据访问审计。[Hebbia Security](https://www.hebbia.com/security/)

**[推断]** 一个人持续使用积累更多历史，首先带来的是这个人的使用价值和切换成本。只有新用户加入确实提升其他用户的效果，才能称为网络效应。专业用户的独有方法、非公开研究和失败记录未必愿意共享。资本叙事不能写成“客户越多，所有人的投资 alpha 自动越强”。

可共享层更适合先积累经过授权的通用错误分类、评测任务和数据质量修复方法；个人观点、持仓、方法和资料保留在私有层。即使脱敏，也仍要核对合同与再利用权，不能假定脱敏产生商业授权。

**与 BP 的关系：** BP/spec 已有分层与授权；新增的是商业含义：个人留存资产、共享技术资产与网络效应应分开计量。历史数量不是壁垒本身；应问“合法拥有哪种独特历史，是否改善效果或交付成本，竞争者能否从供应商重建”。

### 6. 能养活一人和适合风险资本是两道不同的题，不必用同一张评分表

**事实，内部文件 VERIFIED。** BP 目前定位自用 Demo 外部验证前，财务是条件情景；已经列推理、免费层分摊、数据和专业评估预算，也承认模型成本尚未覆盖全部审查/失败/重试。[财务假设](/Users/a77/finance-workspace-private/docs/bp/2026-09-foresight-financial-assumptions.json)、[BP](/Users/a77/finance-workspace-private/docs/bp/2026-09-finance-agent-bp.md)

**[推断]** 若用户想要可持续的一人事业，核心是净现金、续费、每天实际维护工时和创始人生活质量；无需先证明巨大市场。若要风险资本，核心会转向同一细分人群的重复付费、可复制获客、账户扩张，以及收入增长是否不再需要同等增长的创始人服务时间。技术终局完成不等于取得这些证明。

必须加入的经营账：首次导入/框架结构化工时，人工审查与异常修复工时，重试与退款，客户资料授权费用，售前和售后。当前“实收减推理”不能直接当完整软件毛利。机构试点的第二、第三家是否部署更快、维护更省，通常比首张大额定制合同更能检验可复制性。

**与 BP 的关系：** BP 已有现金与阶段退出条件；新增是把创始人注意力作为稀缺成本、把一次性服务与经常收入拆开，并明确融资路线不是个人订阅的必然升级。

### 7. 商业闭环可围绕“可审查的过程”获客与续费；底座/API 的机会要由重复购买倒推

**事实，VERIFIED。** Bloomberg、AlphaSense、Hebbia 都把产出接到现有团队交付物与工作流程，提供源码/引用/Excel 或项目共享等衔接方式，而不只停在问答结果。[Bloomberg AI](https://professional.bloomberg.com/products/bloomberg-terminal/ai)、[AlphaSense 文档](https://help.alpha-sense.com/hc/en-us/articles/53909448564243-Getting-Started-with-SuperAnalyst)、[Hebbia 投研用例](https://www.hebbia.com/blog/how-hedge-funds-use-hebbia)

**[推断]** 可测试的闭环：公开展示一条有来源的判断及后来如何修订 → 用户带自己的旧案例来试 → 当天产出能带走的复盘单 → 持续记录几条观察剧本 → 每周看到减少的漏检/重复劳动 → 为持续维护付费 → 同事通过可分享的证据包加入。公开内容应展示过程、失败和限制；被邀请分享的只有本人有权分享的内容。

个人产品可以先靠轻量订阅，机构可按固定研究流程的持续维护收费。若多家客户反复购买相同的回放、验证或证据接口，才考虑把这些做成可嵌入第三方工作台的底座服务。不要因为技术可复用就同时开个人 App、课程、机构 FDE、数据售卖和 API 五条线。

**与 BP 的关系：** BP 已有公开内容获客与 FDE；新增是让可交付的复盘证据包承担获客、激活、协作扩散的同一个载体，以及把接口商业化设为重复采购后的选项。可带走的格式能减少首用顾虑；长期留存应来自持续维护价值，不靠锁住用户原始记录。

## 下一步最小验证建议

以下是研究推断，不是已经获得的用户需求：

1. 用已有两个入口做对照：愿意建立框架的人、已经有框架且持续研究的人。每类都给同一份“旧判断变更单”，观察哪类人在没有创始人催促时复用。
2. 机构探索先找一个“周会前核对旧判断”的角色和任务，仅做访谈与样本验证；无须因 BP 将交付列在订阅之后而延后了解采购条件，也不因此提前承诺上线机构系统。
3. 统一记录价值与成本：原任务时间、漏检/误报、证据复核率、下周是否回来、谁愿支付、付费后创始人每用户/每团队工时。
4. 外部用户开始连续返回后，再决定优先个人校准、团队交接或方法检验服务。方法有效性继续独立受统计检验，不以留存证明规则能预测市场。
