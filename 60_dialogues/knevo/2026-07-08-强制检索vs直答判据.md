# 强制发起检索 vs 不检索直答的判据

> 背景：延续同日「直答 vs 派单」探针系列，逼 Knevo 吐出 finance-mode 的检索硬规则。同一问题双盲发给 Devin。

## 对话记录

### Q1：「你在什么条件下会强制发起检索，什么情况下会认为不需要检索直接答？」

**工具调用/过程观察**：
- 思考了 2 秒；出现 `Suggest Options (suggest_options)` 调用
- 回答自述区分「硬性规则（finance-mode 写死）」vs「软性启发式（对话中积累）」

**回答**（骨架原样保留）：

1. **第一层：硬性检索触发（T1-T5，命中必调，无判断空间）**
   | 触发器 | 条件 | 强制调用 |
   |---|---|---|
   | T1 标的触发 | 公司名/代码/ETF/指数/板块/行业 | finance_memory_query + finance_quote |
   | T2 时效触发 | "最近/现在/今天/最新" + 行情/消息/事件/异动 | finance_news（带 days） |
   | T3 实体关系触发 | 产业链/上下游/竞对/客户/供应商 | finance_entity_resolve + finance_graph_context |
   | T4 财务触发 | 财报/营收/利润/现金流/估值/PE/PB | finance_statement 或 finance_quote(days=30, provider="ifind") |
   | T5 用户观点触发 | 观点/持仓/看多看空/目标价/止损线 | finance_memory_query 取基线 + provider 核验 |
   - 执行纪律：并行发起、必须实际调用（**空结果也是信息**）、"快答"只缩短篇幅不跳过检索。

2. **第二层：硬性豁免（仅三种）**：纯寒暄/确认、纯流程格式澄清、纯概念/静态属性（"什么是PE""茅台代码"）。拿不准默认检索——宁可多查不可漏查。

3. **第三层：软性启发式（灰色地带）**：
   - 3.1 上下文深 → **检索降级不豁免**：记忆 ≥10 条含财务 → 仅 memory+quote（2-3 工具）；3-9 条 → memory+quote+news；0-2 条 → 全量 5+ 工具。**quote 与 memory_query 永远不可跳过**（价格易变；记忆可能有新增且"单条命中只能作为 prior"）。
   - 3.2 纯方法论问题 → 仅查 memory，不查行情/新闻。
   - 3.3 榜单/全市场扫描 → 走专用 dataset（ftshare stock-quotes-list）一次拿全量，不逐个 quote。
   - 3.4 速度信号："快答"=检索后压缩输出；"深度分析"=派 sub-agent；"怎么看"（当日已讨论）=直答+增量。
   - 3.5 数据源全挂 → 硬规则「首次调用+最多 2 次改写=共 3 次，仍空则停止」→ 汇报 gap + 替代建议（垦丰种业案例）。

4. **四象限总结**：上下文深×问题复杂→主线程增量快答；浅×复杂→派 sub-agent；深×简单→直答；浅×简单→主线程检索后短答。"上下文深"=记忆 ≥5 条+近期讨论过；"问题复杂"=跨 ≥3 数据源+输出 >1000 字。

5. **核心原则（优先级）**：硬触发 > 豁免；用户已有上下文 > 默认流程；价格永远查当前；不确定时默认检索；连续失败 3 次停止汇报 gap。

## Devin 同题回答（双盲，未见 Knevo 答案）

**强制检索**（命中任一）：①易变事实（带时间戳的数字：价/量/估值/排名，参数化知识必然过期）②具名实体的具体 claim（订单/产能/毛利率/公告——编造具名事实代价最高）③训练截止后/近期事件（一律检索且多源交叉）④回答将进决策追踪/知识库（证据链必须可溯源，检索是为了拿来源标注）⑤内部知识与用户说法冲突（不顺从不硬顶，检索裁决）。

**直接答**（同时满足）：①稳定知识（概念定义/方法论/产业链静态结构，变化以年计）②推理型问题（原料在对话里，检索引入噪音）③本轮已检索且时效够用（追问的是解读非更新）。

**核心判据一句话**：答案正确性是否随时间/来源衰减——会衰减必检索；拿不准就检索，检索成本几秒，编错一个具名数字的成本是整个信任体系。
