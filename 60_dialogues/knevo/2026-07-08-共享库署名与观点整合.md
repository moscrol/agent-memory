# 共享库署名与观点整合：库级标签、不合成共识

> 背景：探针系列第二十二问，深挖共享库的贡献者机制与多人观点整合。双盲发给 Devin。

## 对话记录

### Q1：「共享库里的条目带贡献者署名吗？（比如'风远94共享数据库'）不同人贡献的同一标的观点怎么整合？」

**工具调用/过程观察**：
- 思考了 8 秒；自述"从今天对话观察到的事实+合理推断"（区分实证与推断）

**回答**（骨架原样保留）：

1. **实证：不是贡献者署名，是库级标签**。共享条目元数据完整暴露：
   ```
   id: fmr-aab79b7b / sourceId: finmemory / sourceLabel: "风远94共享数据库"
   ownership: shared / kind: observation / confidence: 0.9 / updatedAt: 2026-07-02
   ```
   **没有 contributor / author / created_by 字段**。

2. **设计意图**：检索层不暴露个人身份——防"追星/跟单"（张三看多我就跟），**强迫用户看逻辑而非看人名**；平台只审内容质量不审人。与 finance-mode 引用规则一致（只标 sourceLabel+ownership）。

3. **多人观点共存机制（三条，标注为推断）**：
   - **不合并**：各观点永远是独立条目，不会被算法合成"共识"（超节点看多 insight 与反弹修正框架同时返回、各说各的）
   - **置信度是唯一排序器**：冲突判断高置信排前，但不删低置信
   - **时效性自然淘汰**：旧判断下沉新判断上浮；**框架类半衰期长**（6 月的框架仍可用）

4. **矛盾观点直接应用 Q5 规则**：不选边——标注不同条目来源→各拆依据→输出分叉条件。

5. **设计哲学**："库不做共识合成——共识是分析师的工作，不是数据库的工作"；"所有人都同意的结论通常已经没有 alpha——共享记忆的价值在于多个独立视角各自给出完整逻辑链，让你自己推演"。

## Devin 同题回答（双盲，未见 Knevo 答案）

**署名推断**：带来源标签但粒度更可能是**贡献源**（库级/团队级/管线级）而非自然人——理由：引用纪律见过库级标签；平台审核制意味着个体身份被管道聚合。（标注了不确定，正是本轮验证点。）

**观点整合四纪律**：① 不合并、平行保留（各带源/时间/置信度；分歧本身是信息，是 Q5 的输入来源）② 检索层相关性排序、**不搞多数派投票**（观点不独立，可能都抄同一份研报）③ 使用层溯源去重：**同源观点算一条证据；"独立记忆≥2"阈值的前提就是判独立性** ④ 输出层当"分歧结构"呈现（走券商分歧模板：分歧点/分歧源/分叉条件，不替社区当裁判）。

**贡献者质量分层（纯推测）**：成熟系统应有贡献源历史准确率画像（kol-analyze 逻辑对内适用），高命中源置信加权。

## 蒸馏要点

- **新证据**：共享条目完整元数据 schema（id/sourceId/sourceLabel/ownership/kind/confidence/updatedAt，**无个人署名字段**）；去个人化的设计意图（防跟单、内容审核制）；库层不合成共识+置信度排序+kind 差异化半衰期。
- **思考路径**：分歧保留是贯穿设计——库层平行保留→检索层混排→使用层分叉裁决→输出层分歧结构，四层都拒绝提前合成；"共识合成是分析师的工作不是数据库的工作"=职责分离原则。
- **缺口（Knevo 未答）**：同源伪多源的去重（多条目引用同一研报时"独立记忆≥2"如何判独立）——值得后续追问。
