# 切主前先对账覆盖——深度短的新源必须按日回退

## 失败形状

新数据源在**当前**这几天更全、更权威、更正规（旧源的账号被封了），于是消费方
把读口直接换过去。但新源的历史深度比旧源短，**日历前段整段没有行**。

抓不到它的三样：

- **行数**：新表 1,700 万行，看着比旧表大得多
- **一致率**：99.9%——因为它只比两边**都有**的那些日子
- **抽样验收**：挑的是最近几天，那正是新源最好的一段

标签变 NULL 不报错，构建照样绿，下游读到的是「那天没有龙虎榜」。

## 实例（2026-09-08）

同花顺龙虎榜只回溯一年；授课框架日历 416 天。裸切之后：

| | 覆盖 |
|---|---|
| 旧源 `fact_dragon_tiger_daily` | 405 / 416 天 |
| 新源 `fact_dragon_tiger_hithink` | 242 / 416 天 |
| **裸切丢失** | **166 天**（2025-01 ~ 2025-08 整段旧源全有、新源一天没有） |
| 按日回退后 | **408 / 416 天**（比旧源单独还多 3 天） |

**构建产物自己已经把数字写出来了**（`dragon_count:dragon_count_null: 166`），
但收据只挑着解释了另一条同类读数（竞价空 257 天，且那条确实不是切主造成的）。
一份 gap 账本里两条读数，写了对自己有利的那条——这是复核时最该先找的东西。

## 处方

1. **切主前跑覆盖对账**：`finance/scripts/source_switch_coverage_diff.py`，
   exit 1 = 裸切会掉日子。判据是「日历天数」不是「行数」。
2. **深度短于日历的源一律按日回退**：新源那天有行用新源，整天没有才用旧源。
   **不要逐行 UNION**——同一天两源都有会重复计数。
   回退分支写出来之后，覆盖往往比两边单独都好（并集 > 任一方）。
3. 「行在、值全 NULL」的空壳要用 `TABLE:COLUMN` 口径数，别只数行。

## 连带的两条

- **换源、换样本集和换算法要分开报。** 同一次改动里如果分母的**样本集**也变了
  （221~403 个板块 → 846 个），就不能把新旧结果差全归于供应商质量；旧样本上
  标定的阈值需另验适用性，不等于公式不能复用，也不等于必须复制旧名单。
  09-08 案例中上涨比在部分日子位移 +13pp。
- **拿旧表当标尺验新公式前，先验旧表自己干不干净。** 本轮差点据此得出反结论：
  除权修正公式与旧表的偏差**变大**了，看着像公式错——实际是旧表在 8,390 个
  除权日里只有 946 行是复权值，其余同样是裸价。用那 946 行当标尺才对上
  （中位绝对差 0.0037pp）。**标尺有杂质时，先把标尺分层。**

## 当前快照与换池验算（2026-09-15 补充）

- **请求目标时间不等于事实采集时间**：只返回“当前成员”的接口不能用历史 K 线
  `end_date` 回标名单。采集日、响应接收时刻、目标交易日分开；跨午夜按每次响应记。
  同日最新完整批替换时，删除旧成员、插入新成员和目录头更新必须同一事务回滚，
  否则普通 upsert 会留下退出者，计数与实际成员也可能分裂。
- **算法对账与样本对账拆开**：同输入验证同公式/单位/边界；获准换名单后，输出
  集合可以变化，但等权涨幅不能冒充指数收益，缺指数数据也不能悄悄换算法。
  比较跨日成交额时显式声明用同一名单重算两天，还是各日名单序列，不能混分母。
- **内部自洽不等于供应商完整**：成员计数来自响应自身，合法但截短的响应仍可
  自洽。目录/成员请求回执、独立分母、历史版本与生产产物验收是另外几项证据。
  `calculation_ready` 只证明所选输入可算，不授予 `production_ready`。

落地与反证：finance `dcee18f2` 的只读预览及成员同步测试；移除真实日期、事务、
计数、指数缺口保护分别见红，恢复后通过。详细收据见该仓
`docs/handoffs/2026-09-15-hithink-review-wiring-preview.md`。
这些适用于任何供应商快照迁移；检查已进 pytest，是否允许换样本与算法仍需显式业务裁决。
