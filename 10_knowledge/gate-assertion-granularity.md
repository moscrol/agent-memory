# 门禁的断言粒度必须匹配它声称保护的东西

`gate-covers-only-its-return-value` 说：**一个我见它成功过的检查，只覆盖它返回值所及的范围。**
这一条是它的邻居：**一个覆盖面正确的检查，仍可能因为断言太粗而放过它要防的东西。**

## 核心判据

**写完门禁后问一句：它声称保护什么？它实际断言的是什么？两者差几档？**

差一档就够出事——因为门禁**通过时是沉默的**，粒度不足不会以「失败」的形式暴露，
只会以「一直绿着」的形式存在。

## 三个实例（都实际发生过）

### 1. 只钉路径，保不住符号

`agent-memory/scripts/graph_audit.py` 早期只校验「主要路径」那一格里的**文件存在**。
2026-08-05 撞到：能力图谱写着 `episode_tools.py` 提供 `memory_lookup`，
而该符号**只存在于一条未合并分支**；`episode_tools.py` 本身在 main 上存在，
于是**只校验路径的门禁 exit 0**。

它声称保护的是「图谱不过期」，实际断言的只是「文件还在」。中间差了一整档：符号。

修法是把断言粒度补齐成三级：

```
`intelligence/services/cli.py`                     # 路径存在
`.../research_tool_registry.py::memory_lookup`     # 符号在该文件里
`.../episode_tools.py::memory_lookup@some/branch`  # 在指定分支上（在途能力）
```

### 2. 拿文件系统事实断言版本控制事实

`check_inflight_stale.sh` 早期判「交接是否过期」，用的是「代码路径前缀 + mtime 比文档新」。
2026-08-11 实测误报：本分支被 3 个完全不相干的脏文件判成过期，
而那 3 个文件本分支 8 个提交一次都没碰过。

它声称保护的是「本分支干了活却没交接」，实际断言的是「这棵树上有比文档新的文件」。
**未提交改动在 git 里没有分支归属**——它只属于这棵树，不属于任何分支。

更隐蔽的是：那次它**结论对、理由全错**（交接确实过期，但真实原因是分支又提交了两次，
两者时间只差 2 秒）。**「报警响了且事实成立」不等于「判据成立」。**

### 3. 断言了终态，没断言它保护的中间物

「测试全绿 ⇒ 零行为变更」是同一个形状的推理错误：全绿只说明**没有测试钉住修复前的语义**。
异常类型不变 ≠ 抛不抛不变。要证伪得用「把 HEAD 改动的测试搬到未改动的基线树上跑」
（`baseline_diff.py --mode probe`），因**断言**变红才是证据。

## 处方

1. **写门禁时把「声称保护什么」写进注释**，然后逐条对照实际断言的量。
   差档就补，补不了就在注释里**声明它保不住什么**——声明过的缺口不算陷阱。
2. **exit 0 必须自述它对哪个 revision 成立。** 一个不带条件的绿灯，
   在下一个 agent 眼里和「没跑过」等价（见 `evidence-hygiene-three-failure-shapes`）。
3. **验门禁要查它引用的证据，不能只看结论对不对。** 实例 2 就是结论对、证据错，
   如果只核对结论，这个缺陷会一直留着。
4. **粒度不足的典型信号**：门禁的判据里出现「存在性」「计数」「时间戳」这类
   *代理指标*，而它声称保护的是「内容正确」「归属正确」「语义未变」。
   代理指标和被保护物之间每差一层，就多一条能悄悄溜过去的路。

## 可迁移场景

- 任何「清单/地图/文档必须跟上代码」的门禁（能力图谱、API 文档、依赖清单、changelog）
- 任何用 mtime / 存在性 / 行数 当判据的检查
- 测试断言本身：断言返回值 ≠ 断言副作用；断言总数 ≠ 断言集合（修好 3 条 + 引入 3 条，总数不变）
