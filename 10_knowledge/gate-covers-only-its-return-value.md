# 闸门覆盖不了旁路副作用

`evidence-hygiene-three-failure-shapes.md` 形状三说：**一个我没见它失败过的检查，不能信。**
这一条是它的下一层：**一个我见它成功过的检查，也只覆盖它返回值所及的范围。**

## 核心判据

**给一段逻辑加防错闸门时，先问「这段逻辑除了返回值，还写了什么」。**
写在别处的副作用，不受返回值路径上的闸门管辖。

## 三个实例（2026-08-11，dao-proxy-pro）

### 1. `_errorType` 闸门 vs `isError` 旁路

给工具结果做「防投毒」：输出长得像代码就放行（`looksLikeCode`），有运行期信号才记错。
闸门加在 `_errorType()` 的**返回值**上，测试也验了「该放行时放行」。全绿。

但 `isError` 在**上游**独立计算，它写了三个字段：
`lastToolOk`、`consecutiveFailures`、`sameCallFailureStreak`。这三个都不经过闸门。

结果是：`lastError` 干净了，状态栏照旧在说假话——工具成功返回含 `ENOENT` 字面量的
源码时，被记成失败，`strategy` 据此建议「verify path」（方向反了）。

### 2. 消息级断点有门槛，system/tools 断点没有

同一个 4 槽预算，消息级断点做了最小 token 过滤，`system`/`tools` 断点无条件打标。
实测 system 1 token + tools 3 token，模型下限 4096 → 两个必然 no-op 的断点各占一个槽位，
挤掉了真正够大的候选。同池两套判据，只有一套上了闸门。

### 3. 测试判据被自己要测的改动污染

写 `prompt-cache-min-tokens` 测试时，用 `breakpointCount >= 2` 当「消息级断点是否授予」
的代理指标，隐含假设 system 断点总占 1 个。而 system 断点正是本次要加门槛的对象——
判据被被测改动改变的量，报出的失败方向是反的：看着像分档表错了，实际是代理指标错了。

## 处方

1. **审计副作用**：给函数加闸门时，列出它写的**所有**字段/状态，闸门必须覆盖全部，
   或明确标注哪些字段不受保护。测试断言要覆盖被写字段，不是只看返回值。
2. **代理指标要验证正交性**：测试里用「总量」当「分量」的代理时，确认总量不会因被测改动
   而变化。`breakpointCount` 就是反例——它本身就是被测逻辑的输出。
3. **同一资源池的判据要一致**：4 个槽位、同一个门槛，不该一段有过滤一段没有。
   一致性缺失本身就是 bug，且通常藏在「顺手」里。

## 完成统计不能只信生产者（2026-09-16，L2 文件源）

## 派生附注不能证明原始正文存在（2026-09-18，pi）

金融研究保留候选 `feat/research-answer-preservation@5f3b5b59` 两次出现同形漏洞：先把秘密清空，再加核验/单源/过期来源说明，最后用“非空”判断有答案。附注把空稿复活了；只测脱敏helper会漏掉真实调用顺序。

还要分清保护范围：本轮一次真实产品会话末端保住979字已准入稿、诚实保留rejected/partial，但更早两次终稿因格式/内容准入失败被替换；整体保留验收仍未过。**末端稿逐字一致，不证明上游生成史没有丢稿。** 排查要沿每次候选产生、拒收、修复与公开投影核对，而非只测最后出口。当时准入前漏洞待新片修复，不拿原门撤销换取“完成”；安全身份、证据完整性与正文展示资格分开。原件与收据见金融本枝 `docs/verification/2026-09-18-research-answer-preservation/README.md`；这是一条有界方法与正式回归，不另造通用运行框架。

**同日续片（35ee8a5c，作者离线）**：把候选保存与准入/核验拆开；恢复必须承接成果**及其实际证据依赖**，只保存正文却裁掉它用到的来源，仍会逼下一步重写。后稿逐字包含旧稿仅免重复，不能抹掉待复核状态；取消后成果可保留，执行仍取消。八类内存撤保护均见红、原逻辑68P，固定真实原件两路径保住四段并诚实partial；原live不改判，进程崩溃后恢复仍未实现。适用于报告审批、编译诊断和分阶段生成：成果存在、身份安全、质量通过、工作完成分别记账。机械保护在正式回归及 `scripts/replay_finish_candidate_preservation.py`，详细边界见本枝 `docs/handoffs/2026-09-18-finish-candidate-preservation.md`，不另造通用框架。

## 执行、质检与人审不能合并成一个成功位（2026-09-18，运营/视频）

## 检索过滤与扩读的证据范围（2026-09-18）

请求L3或截至日，只证明调用方想要它；不能把请求参数原样填遥测，就当执行端做到了。
旧CLI不支持时删参数重试，会把硬约束降成偏好。应核对实际过滤回执与逐条元数据，并区别
“合法空结果”与“旧索引缺字段”。回执不是恶意生产者的身份认证，也不代证每条事实正确。

通过过滤的片段之后若被原页重摘录、整节深读或stale恢复替换，新文字不能继承原等级/时点。
有界做法是锁住已核验范围；需要扩大范围，重新经过同一过滤者，不能只沿用旧标签。
同理，磁盘脚本升级不代表常驻进程升级：负能力缓存与进程加载身份都要失效；同mtime/size
的旧Python字节码也要排除。生产仍应不可变检出+重启，不把指纹检查当热部署事务。

金融 `fix/kb-filter-receipt@698555e2` 与KB `fix/agent-retrieval-reliability@1f614b694` 的正式
回归覆盖旧协议拒收、扩读禁止、真实CLI/worker及源污染；两项代码升级先红后绿，查询中变化
弃响应后可重启恢复。只证明作者离线合同，未部署、未验真实模型质量。可迁移到法律/医疗RAG、
带权限的数据导出和后处理。机械保护已进测试，不另建第二套人工检查清单。

**同日复查延伸（运营/视频）**：`ok=true` 仍可来自零扫描/零采样，报告列了截图也不等于文件存在；平台例外词还能绕过隐私。content-ops `cdc49db` 先验契约形状再验语义，privacy 不接受别名豁免；vidio `0d7af51` 交叉核对覆盖与工程内非空产物。覆盖/存在仍不证明视觉正确，人工审片独立。

最终写入也要防竞争：开跑前“文件不存在”不能保证渲染期间没有别人写入。先写同文件系统临时文件，成功后原子独占创建最终路径；真实 shell 回归涵盖失败半成品、文件/目录竞争和不覆盖。依赖同理：目录存在≠版本已核对，恢复前用完整 Git ref 和目录哈希核验，拒绝覆盖本地修改；先追溯 hash 漂移来源，不能按现状改锁刷绿。正式恢复器/回归及正反例收据见两仓 `docs/handoffs/2026-09-18-review-hardening.md`。可迁移到报告导出、依赖恢复与数据落盘，保护在实际消费者/写入者，不另造通用平台。

**同日四项续查（运营/视频）**：保护一个渲染入口，不等于旁边的混剪/API/复制命令也受保护；必须枚举所有最终写入出口，并真执行复制命令验证引用与失败清理。请求端口也不等于实际端口：服务可能自动换端口或复用会话，应读取实报地址后核对消费者的工程身份和精确版本，不能把请求参数当回执。新文件存在也不等于已审核，界面必须显式选版本并展示当前文件，刷新不悄悄替换选择。vidio `7b6db55` 的真实 FFmpeg/shell/HTTP/浏览器回归及占用端口后的真实 CLI 验证落在正式测试；content-ops `3d2bce5` 同步修掉 skill 中与契约矛盾的算法断言。可迁移到报表导出、多服务启动器、文档修订与多入口政策；PNG 未目视，不据此认证审美或发布。收据见两仓 `docs/handoffs/2026-09-18-output-preview-followup.md`。

## 可迁移场景

- 任何「净化/校验/分类」函数（正则、白名单、去重），先找它除了 return 还改了什么
- 测试断言面：只断言返回值 + 不测副作用字段 = 闸门在，旁路敞开
- 仪表/监控数字：读数来自多条写入路径时，一条路径上了闸门不等于全部路径干净

## 权限副本延伸（2026-09-14，金融 E2 P3c）

Scope 内拿到受限注册表，不代表持有原注册表的运行器也受限。E2 反例：工具执行会拒绝，但原注册表的开场预取已经进入首轮模型消息；未知 IO 工具也先进入菜单。只测 dispatch 拒绝，测不到这两条旁路。

修法不是原地修改调用方对象，而是在每个消费者拿数据前绑定同一个只收窄的权限投影：配置快照、提示词、账本播种、菜单/定义、批执行、修复续轮。晚到的未认证预取/加载器仍应在重新绑定时被清掉，不因「当前上限相同」提前返回原对象。普通 full 上下文维持原对象；这不是恶意 Python 隔离，也不能撤销上游工厂已经做过的 IO。

机械保护已进 `fix/e2-boundary-closeout@b4ba6fb5` 的 `test_e2_runtime_ceiling.py`：检查模型实收消息、账本、菜单、解析尝试与派发意图；同时保留认证本地 runner 能执行的正例。相同15针在修补前12红/3绿、修补后全绿；这是作者行为测试，不是独立验收。模式可复用到租户权限与净化对象副本；无需再建第二套扫描器。

## 计划传递延伸（2026-09-14，日报门禁）

生产者按 local 执行，不代表后续质检也按 local：子进程各读默认值，恢复执行和 HTML 嵌套质检还会再分叉。只增加入口配置、只测同步器或只看最终 PASS，都守不住这种契约漂移。

处方：入口解析一次有效计划，对每个子消费者显式传递；尚不支持该计划的生产者要拒绝，不能悄悄跑全量然后按 local 放宽检查。测试应在 options 创建后改变环境，验证所有下游 argv 仍保持原计划，并临时删掉一处传递让测试转红。金融 `fix/local-plan-gate-alignment@4fbc8c42` 的 `tests/test_review_plan_alignment.py` 覆盖恢复入口、两门及 HTML 内部门；删跨日 --plan 后 9F、恢复后针对性 144P。最初 /tmp 全量另有沙箱两项红；后查明 minimal 允许读取 /tmp，/Users 同代码复验通过。历史红收据保留，不以“基线也红”代替定位或整体发布结论。可迁移到 ETL 档位、租户配置、离线/在线模式；保护已落测试，不另造排查工具。

## 代码装载与写入归属是两道门（2026-09-15，日报#50）

`import` 来自新快照，不代表子进程脚本也来自它，更不代表产物仍在旧数据根。`PYTHONPATH` 不能覆盖裸 `-m` 的 cwd 优先级；`-P` 不会改相对脚本执行文件；粗暴 cd 到快照又会让依赖 cwd 或 `__file__` 的输出漂移。
