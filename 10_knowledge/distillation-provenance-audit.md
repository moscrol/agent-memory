# 炼化对账：用「可追溯引用」判定一份原料有没有被蒸馏

## 结论 / 要点

被问「我沉淀的 X 资料还有没有没炼化的」时，做**原料 → 处置决定 → 产物 → 消费者 → 验证证据**的血统表（provenance / lineage）。编号/路径指针用于快速定位，不能独自决定内容有没有吸收。

> 有指针只证明可追溯；没指针先记「来源链待补」，再核内容。已实现、已投递、已验证分开。

09-16旧版「编号零引用即未炼化」已被同日画像去重对账推翻，09-23再次按当前内容核到旧候选已进入字段：同一母本经不同编译路径会改写措辞、丢失编号。内容对应须列字段位置、主张/适用条件/失效边界和来源证据；只有大意相似仍不够，也不能因无ID重复灌入。

## 做法（六步，半小时内）

1. **先分层再点名**。原料通常有四层：原始导出（对话原文 / zip / 截图）、整理语料（qN 文件）、实验记录（E / AB / D 系列）、炼化产物（vault 知识页、仓内 spec、代码里的 `source=`）。每层各列一张清单，缺哪层就查哪层。
2. **以合并目标分支为准，不以手边检出树为准**。主树曾落后 729 个提交，目录里看不到最近三批语料和状态台账；先 `git ls-tree -r --name-only <integration-branch> -- <dir>`，再 `git branch -a --list '*<topic>*'` 把未合分支逐条 `git log --oneline main..<b>` 过一遍——最新的原料几乎总在未合分支上。
3. **先搜引用，缺引用再做内容对账**。编号/文件名/日期用于定位；无命中再按主张与条件查当前字段、版本与审批记录。逐项记内容对应或冲突、字段坐标和来源，修复血统缺口，不把编号命中率当吸收率。
4. **收窄负面断言**。grep只能证明指定范围无匹配，不能写成「内容未吸收」的实测结论；内容是否缺席须检查实际承载与消费者，未核到就保留未知。
5. **按价值排序而不是按发现顺序**：原始导出层的洞最贵（一份 470KB 原文只蒸了 1/44 轮），实验层的洞最便宜（补一条 verdict）。
6. **产出两样东西**：一张带状态列的对账台账进仓（短摘录即可，原文全文不进 git），加一份「明确不吸收 + 理由」——没有这份，下一个人会把同一堆原料再盘一遍。

## 边界与反例

- 有引用 ≠ 炼化到位：q13 有 `degraded_fallback.py` 指回，q14 只有一句「口径抄 Knevo 信源分层」——后者要再按子项拆（判定四档 / 三层拆解 / 数值权重）才知道吸收了几分之几。
- 引用可能指向已删的路径（vault inbox 会清空、worktree 会拆）。归位时把被引用的原件搬进仓、改指针，别只删。
- 同一母本两条编译路径（运行时检索正文 vs 编译成规则集）会让「已炼化」看起来像「未炼化」，先查 `source=` 标注再下结论。

## 可复用检查清单

- [ ] 四层清单各一张，含未合分支
- [ ] 每份原料一行：编号 / 路径 → 指回它的产物 → 判定 → 建议动作
- [ ] 无引用与内容缺席分开；负面断言带检索范围及内容核对证据
- [ ] 已实现 / 实际消费者已收到 / 效果通过分开，真实失败不被单测绿覆盖
- [ ] 台账进仓，全文不进仓
- [ ] 「明确不吸收」段写理由

## 09-23反例与工具边界

专项指导的ask单测能绿，Workbench材料入口却可能换成通用题型而收不到规则；completed消息也可能只剩降级模板。公开report的frame还可能被清洗，不宜倒推真实模型输入。金融分支已把重复取证固化为 `intelligence.eval.knevo_regression.inspect_run`：run/题面身份、私有或公开frame来源、工具请求与工件哈希分别记录，缺审计不记零IO，永不自动签语义通过。

内容对应、外部后端真相与回答质量仍需逐项语义审查，尚不能包装为通用自动评分器。原料/画像对账与12题证据留金融 `docs/learning/knevo-distill/final-report.md` 及其指针；方法适用于技能蒸馏、规则迁移与旧系统接替，而不是只适用于金融。
