# Knevo 逆向补充会话（2026-09-10）

> 本次由用户直接追问 Knevo 四轮（数据加工诚实度 / 检索架构与精度 / 长内容处理与超时恢复与质检门 / 数据源权威度分层 / 竞争壁垒自评），Knevo 给出的回答比 2026-07-08/08-07 两轮更坦诚、更具体。以下按主题整理，证据分级沿用主文档约定：**[自述]** Knevo 主动描述、**[实测]** 行为或交叉验证反推、**[推断]** 我们的推理。

## 1. 数据加工层次（[自述]）

Knevo 自己拆了三层，和 `[[knevo-reverse-engineering]]` §2 的"数据源=commodity"判断吻合，但更细：

1. **底层原始值（尽量原样）**：价格、财报指标、两融余额、股东持股、陆股通持仓、期权链、一致预期——工具返回什么就是什么，不改。
2. **它承认真正加工、误差主要出在这里的环节**：归纳摘要（JSON→文字，可能丢信息串行）、**时间标注**（"披露日"vs"抓取日"、"盘中价"vs"收盘价"，它自称"最容易出错的一环"）、多源综合（几个 provider 的 as-of 不一致时错配）、去噪筛选（宽召回结果里筛核心/噪音，筛错则结论偏）、推理/情景判断（这部分完全是生成的，非数据）。
3. **研报深度边界**：A股研报只有标题+摘要，非全文；美股/港股研报完全没有本地库，走 web 二手来源。

## 2. 检索架构自述：明确否认是传统 GraphRAG（[自述]）

Knevo 原话：**"严格说，不是传统意义上的 GraphRAG"**。四路并行检索：

| 通道 | 内容 | 用途 |
|---|---|---|
| 记忆检索 | 关键词+语义混合（个人/共享分层） | 历史观点、框架、复盘 |
| 实体图谱 | SQL 支撑的实体-关系-事实图（1-2跳邻居+证据片段） | 消歧、产业链/竞对传导 |
| 金融数据 provider | 行情/财报/新闻/研报摘要/期权/两融/北向/股东 | 当前事实 |
| web 检索 | 无类型广域召回 | 补漏、开原文 |

它把自己的图明确定位为"实体-关系-事实"知识图谱（消歧+关系解释用），不是"文档切块后用图做索引增强"那种严格定义的 GraphRAG；真正的文本召回主力是记忆库语义检索+provider+web。**这与 `[[knevo-reverse-engineering]]` §3B 已有的图谱描述一致，新增的是它自己明确否认"GraphRAG"这个标签**，值得记一笔，避免我们内部用错术语类比它的架构。

**精度不高的自曝根因**：图谱覆盖率有限（很多公司/关系没入库，查出来是空，它承认"有时会拿关键词结果去顶图谱结论"——这是它自认该改的缺陷，正确做法应老实说 gap）；记忆语义检索召回弱相关噪音；时效性陷阱（陆股通持仓数日一更、股东季报口径、**北向净流入早就停发**——见下节）；研报只有摘要看不到论据；自己的加工环节（时间标注/多源 as-of 错配/归纳丢信息）。

## 3. 长内容处理 / 超时恢复 / 时间预算（[自述]）

- **长内容**：`web_fetch` 工具层自动截断到约 **3 万字符**，全文落盘、用摘要继续；文件读取分页/切片；PDF 有"摘要模式"与"逐页原文"两种。Knevo 自己在生成时还会再压缩一层（归纳排序，丢弃弱相关）；长任务倾向拆 sub-agent，汇总层还会再丢一次细节。**三层压缩叠加，且它承认"如果某个来源被截断，理论上该说但实际有时不主动说——这是缺陷，不是设计"**。
- **超时**：单工具超时返回失败状态，走 provider 降级链→web→用户 workspace 文件→问用户；全失败则明确写"gap"，不编造。重试上限 1+2=3 次（与主文档 §1.1.4 已记录的"重试纪律"一致，非新信息）。
- **时间预算**：单次工具调用有超时（确定存在）；整体 runtime 有上下文窗口/token 预算上限，但**具体秒数/阈值 Knevo 自己不掌握，明确拒绝编数字**——这是"不知道就说不知道"纪律的又一次行为验证，与主文档 §3C 防幻觉原则同源。

## 4. 关键新发现：没有强制质检门（[自述]，重要）

这是本轮最有价值的一条。Knevo 明确说：**没有一道硬性的、自动化的"质检闸门"拦截不合格答案**，只有生成时"应该遵守但可能漏"的规范。它自己列的表：

| 检查项 | 有没有硬闸门 | 实际情况 |
|---|---|---|
| 来源标注 | ❌ 无 | 靠 skill 输出纪律，可能漏标 |
| as-of 时间标注 | ❌ 无 | 靠自觉，它自称"最常出错的一环" |
| 删除内部记录 id | ✅ 有规则 | 但仍靠生成时自查，不是机器拦截 |
| 事实 vs 推断分层 | ❌ 无 | 靠措辞区分，可能含糊 |
| 数据真伪交叉校验 | ❌ 无 | 工具返回什么就信什么 |

Knevo 原话对"没带来源的答案会不会出门"给出的是肯定答案：**会，因为没有能拦住它的自动闸门**。

**这个信息值得我们直接拿来对照自己**：本仓 `intelligence/services/episode_verifier.py` / `episode_semantic_verifier.py` 这一整套判官/语义核验层，就是 Knevo 明确承认自己没有的东西——不是锦上添花，是它自认的架构差距。今天(2026-09-10)另一条线正在推进的"判官修复01"工作，其价值可以多一个参照系：**我们判官的问题是"存在但有两处误挡"，Knevo 的问题是"完全不存在"**，两种缺陷的严重程度不是一回事，误挡了还能修，没有则是从产品设计上就选择不做。

## 5. 数据源权威度分层表（[自述]，本轮最实用的一条）

Knevo 主动做的分级（它自称查了当前 provider 实时状态：**当次检查时只有 datasvc、polymarket、web 三个"ready 无降级"**，massive/ifind/ftshare/gangtise/mx-finance 未必都在线，是某一刻的快照不是恒定状态）：

| 类别 | 底层来源 | 权威性 |
|---|---|---|
| A股现价五档 | datasvc（iFinD/腾讯供源） | 较权威，非交易所直连原始快照 |
| 美股现价 | massive（Polygon） | 较权威 |
| 期权链 | massive（OPRA） | 高权威，OPRA 是官方期权报价系统 |
| A股财报指标 | datasvc（iFinD供源） | 较权威，但是加工后指标值非三表原文 |
| SEC 公告 | datasvc | 高权威，直达监管披露 |
| A股研报 | datasvc，标题+摘要 | 中低，看不到论据/模型假设 |
| 美股/港股研报 | web | 低，二手来源 |
| 两融余额 | datasvc（iFinD专题，T+1） | 权威，盘后口径 |
| **北向成交额/净流入** | datasvc | **权威，但净流入已 2024-08 停发，任何数据源都没有** |
| 陆股通持股 | datasvc | 权威但非日频，数日一更 |
| 十大股东/股权质押 | datasvc（iFinD） | 权威但季报口径 |
| Polymarket | Polymarket | 市场定价，非事实 |
| 知识库(记忆+图谱) | 内部 | **明确不算权威事实源**：个人记忆=主观；共享记忆=他人研究认知，低权威；图谱=有证据可靠，空就是空 |

### ⚠️ 交叉验证：北向净流入停发是真的，[实测] 升级为确证

Claude 当场用本仓已在用的 AKShare 做了交叉验证：`ak.stock_hsgt_fund_flow_summary_em()` 今天(2026-09-10)返回的沪股通/深股通两行，`成交净买额` 和 `资金净流入` **字段值精确为 0.000000 / 0.0**（同一条命令里南向的港股通(沪)/(深)两行是正常非零值 42.6 / 2.9）——不是取不到数据报错，是这个字段被上游清零/停更了，只是接口形状还在。**这与 Knevo 的自述完全对上**：换 AKShare、iFinD 还是任何其它源，都补不了"北向净流入实时数字"，因为这不是某个 vendor 的能力边界，是交易所 2024-08 起不再公开发布这个数字本身。

**对本仓的直接影响**：今天(2026-09-10)早些时候的对话里，Claude 建议过"北向资金可以查 AKShare `stock_hsgt_fund_flow_summary_em`"来补 Knevo 提到的数据缺口——**这条建议要撤回**，该函数现在只能拿到"是否有交易""涨跌家数"这类还在更新的字段，净流入/净买额这两个核心数字是死的。真要做北向分析，只能退回到"沪深港通持股市值"（陆股通持仓，按 Knevo 自己的说法也是"数日一更"）这类替代口径，不存在能拿到实时净流入的路。

## 6. 竞争壁垒自评（[自述]，可迁移的产品判断）

Knevo 对"你的壁垒在哪"给出的自我剖析，坦率到值得摘录：

- **承认数据源是 commodity**："谁都能接 iFinD、Polygon、Benzinga、Polymarket，中间那层数据管道任何人拼得出来，没法在这个层面吹护城河。"
- **它认为唯一真正学不走的**：用户自己在对话里积累的个人记忆上下文——"竞争对手可以一字不差抄我的架构，但抄不走你已经积累的那部分"，这是沉淀在用户侧、不在系统手里的数据飞轮。
- **下游差异化是工程态度不是技术壁垒**：决策追踪闭环（前瞻判断事后回来对账，多数投研 agent 给完结论就完了）+ 反顺从（默认把用户观点当待检验假设，不迎合）——它自己承认这两样"别人不是做不到，是不想承担成本"，甚至反问自己"为什么别人不做"，给出的答案是"付费用户短期更愿意为被验证买单而非被挑战"，坦承这条差异化可能不商业化但是真的。
- **纪律层（as-of/来源标注/时效口径）**：它把这归为"可靠性纪律"而非"技术壁垒"——谁都能学，只是烦、容易漏，价值不在"别人抄不了"而在"决定你信不信它"。

**可迁移的判断**：这套自我剖析的分层方式（数据=commodity / 用户侧沉淀=真壁垒 / 工程纪律=可靠性非壁垒）本身就是一个好用的框架，可以直接套到我们自己头上做同样的诚实盘点，不只是抄它的功能清单。
