# 原子占名不等于完整发布

## 结论

文件写入的四个承诺要分别验证：**占名不可竞争、读者只见完整内容、既有证据不可覆盖、失败后可恢复重试**。

`O_CREAT | O_EXCL` 把“不存在才创建”交给内核一次完成，但正式路径立即可见，后续写内容期间可能是空文件。把它称为“原子写入”会掩盖真实合同。捕获 `BaseException` 后删半截文件，也兜不住 `os._exit` 或强制终止。

## 已复现的失败形状

1. 暂停第一个写手于正式路径创建后、内容写入前：读者看到 0 字节 JSON；相同内容的第二个写手因无法解析旧文件而被判碰撞。
2. 同一位置终止真实子进程：坏文件留在正式命名空间，原内容重试持续失败。若读者静默跳过坏文件，还可能继续发布不含该次写入的旧结论。

这不等于“成功提交的数据丢失”；报告要区分**未提交、损坏残留、成功提交后丢失**，不能把注入故障夸大成已发生的业务事实。

## 方案取舍

- 候选方案：同目录临时文件写完整，`flush/fsync` 后以无覆盖方式发布正式名称，再同步目录；临时文件不进入读者枚举。
- 本地文件系统可评估 `os.link(临时, 正式)`：目标存在时拒绝，继而比对完整内容处理幂等；依赖同文件系统和硬链接支持，不能直接推广到对象存储。
- `os.replace` 适合允许替换的缓存，不自动满足不可覆盖账本；直接替换会把发布修复变成覆盖回归。
- 完整 JSON 和可重建 Markdown 可分别恢复，不必无条件升级为多文件事务；真正需要一组产物一起可见时，再用 manifest/提交标记或事务存储。
- 既有坏文件要有单独告警/恢复策略；不能凭文件名猜内容，也不能为恢复重试随意抹掉证据。

## 验证方法

在各承诺的交接点**暂停或终止进程**，而不只在线程开始前放一道屏障：同内容并发、异内容强制同名、读写交错、写前/发布前/发布后退出、多产物中途失败。验证所有共享同一 helper 的入口。

本次是已有 revision 专用探针的取证，不是通用工具：脚本断言“缺陷存在”，exit 0 不能当修复验收；修复方须转成正向回归。适用于缓存、台账、任务结果和模型产物落盘。

## 补充：原子换名不保证来源与产物身份（2026-09-13）

在 DuckDB staging 换库三轮审查中，用本机真实进程和小型夹具复现两个相邻但独立的窗口：

1. **快照与版本基线脱节**：先克隆旧值，再采来源的最新 stat；期间另一写者已提交新值。末端锁内比较仍通过，因为比较的是被重新指派的基线，最后成功发布旧副本，撤销已提交值。备份保留新值只保证可恢复，不保证此次发布正确。
2. **状态绑定但产物可换**：A 验证本轮状态、候选与收据后暂停；B 将共享候选名当残留删除、重建，随后失败。A 恢复仍按自己的成功状态发布同名但已属于 B 的失败候选。

可迁移判据：**状态标识、候选内容、来源版本、最终发布对象必须属于同一轮；对名字做原子操作不自动保证这四者相同。** 快照阶段需让来源版本与快照在受保护窗口中绑定；运行互斥必须在清理候选前取得，或使用每轮唯一候选并协调最终发布。末端锁与本轮 token 不能替代候选所有权。适用于构建产物、模型结果、缓存刷新与数据迁移。

审查方法：分别在「复制完成→采基线」「验证完成→使用候选」暂停，插入真实竞争者，然后核对最终内容，不只核对返回码。两次均没有恶意裸文件写入；故障来自正常数据库写者及正常第二个编排进程。报告 `~/.finance-runtime/reviews/hithink-9d73f01a-qc/review.md`，专用探针留在同目录；其 exit 0 表示缺陷复现，不是修复通过。未代修生产代码，修补方须转成现有测试内的正向回归，不另造通用工具。

## 补充：缺失也是发布前提，不是免保护状态（2026-09-13）

换库六轮审查（代码 7c89ca81）独立复现：target 初始缺失，最终检查之后普通 DuckDB 写者新建、提交并关闭，再只读读回确认提交；随后 staging 无条件 replace，返回成功却丢掉对方的表。**「开工时不存在」不等于「发布时没有别人已提交的数据」。** 只在既有 inode 上持锁，保护不了缺失路径；同一运行协议的互斥锁也不会自动排斥其他正常数据库写者。

首次发布可评估完整临时文件的 `os.link(temp, target)`：让「仍然缺失」成为内核原子判据，而非先 exists 再 replace。目标存在即拒绝；link 成功已经发布，后续临时名删除失败不能报告「未发布、正式文件未动」。这与按预期 inode 条件覆盖既有文件是两份不同合同，不能混称已闭合全部换库窗口。

同轮另复现：在锁获取处归一 FileNotFoundError，不代表全链目标消失都已归一；克隆元信息的 source.stat 与锁外 exists→stat 仍抛裸异常。沿每一次可失败的文件操作注入，比枚举外层 except 数目更能检验异常合同。

行为边界测试能保存可重复反例，但不会因注释重新声称「已闭合」自动变红。**行为证据不是措辞门禁。** 三条正向安全断言在所审代码均红，报告/探针：`/tmp/daily-swap-qc-7c89ca81/docs/handoffs/2026-09-13-daily-swap-round6-qc.md`、`scripts/review_daily_swap_races.py`（审查提交 e15379f5）。

## 补充：已见对象的消失，不能重解释成首次初始化（2026-09-13）

七轮审查在 dfb6ce87 的首次只读探针成功返回后删除临时旧库；后续独立 `exists()` 得 False，编排重新选择 bootstrap，发布只含新一天的数据并报成功。旧版同红。旧文件由外部删除，不是发布原语覆盖；错误在于**丢掉已观察的 existing 前提，把生命周期中的消失解释成从未存在**。

可迁移原则：初始 existing/absent 决策一旦形成应贯穿本轮；已观察为 existing 后的缺失走拒绝/显式恢复，不静默初始化。修的是阶段之间的状态传递，不是再在发布前加 stat，也不能承诺知道首次观察之前发生过什么。适用于数据库、配置、账本与缓存刷新；是否允许自动恢复须由调用方明确授权。

证据：`/tmp/daily-swap-qc-dfb6ce87/docs/handoffs/2026-09-13-daily-swap-round7-qc.md`，探针 `scripts/review_daily_swap_round7.py`，审查提交 `e8ad314b`（8P/1F，两绿仅是旧 IO 出口的 characterization）。
