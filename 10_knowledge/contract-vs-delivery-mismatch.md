# 契约与交付不符

> **失败形状**：某处向模型（或向下游审计）**承诺**了一件事，实际交付的是另一件，
> **且模型无法自行诊断**。
>
> 这不是 bug 的一种，是 bug 的一**类**。2026-08-12 一天里在**五个互不相干的模块**
> 各命中一次——分散在五处、由不同时间的不同改动引入、彼此没有共同代码。
> 能一天抓到五个，说明它是**架构性易发**，不是巧合。

## 五个实例

| # | 承诺 | 实际 | 后果 |
|---|---|---|---|
| 1 | 工具 schema `limit.maximum = 1000` | runner `min(limit, 25)` | 189 次调用里 55 次（29%）在错误信念下工作 |
| 2 | `{"error": "invalid_arguments", "detail": ""}` | 原因**有**，只是没往下传 | 15 次失败里 14 次同一个错**一模一样重复** |
| 3 | 观测文本「无命中（error）」 | 20/22 是工具故障，不是知识库为空 | 把「查不到」写成「不存在」 |
| 4 | 标题「较早消息**摘要**」 | 尾部截断，最早部分静默丢弃 | 模型以为已概括全部较早内容 |
| 5 | 检索结果（形态完全正常） | hybrid 已降级纯 BM25 | **成功外观下的能力降级**，无任何报错 |

## 四个让它难被发现的性质

1. **静默**——没有异常、没有红灯，输出形态正常
2. **自洽**——模型据此写出的结论内部一致，只是前提是假的
3. **量具同盲**——#5 走 eval 也发现不了：合成 eval 集判别不了 hybrid 与 BM25。
   > 🔑 **量具的盲区与生产的盲区重合时，缺陷可以长期存在，而两边都发绿。**
4. **契约反向加固**——#3 里**我们自己写的**行为契约说「无命中只说明知识库没有
   回填过」，在 status=error 时这句话是错的：**契约在主动教模型误读**。
   写行为契约时要问一句「这句话在所有分支下都成立吗」。

## 排查手法（按成本从低到高）

1. **对每个「广告值」找它的「执行值」**——两个都是机器可读的数就写成硬断言。
   这类等式没有编造空间，可以硬门禁（不像「描述写得好不好」）。
2. **grep 兜底文案**：`or f"无..."` / `or "没有..."` / `else "empty"`。
   `or` 右侧的默认串正是把多种原因压成一句话的地方。
3. **找「填了但没人读」的字段**：`detail` / `degraded` / `fallback_reason` /
   `warning`。**遥测诚实但不往上传**是本类的高发形态——五例里占三例。
4. **对每个降级分支问：模型看得出来吗？** 看不出来就补告知。

### 动态装配时，配置快照不等于执行快照（2026-09-16）

E-008 工具投影修复（finance `fix/audit-followup-0916@ef1d56f5`）：configure 发生在沙箱/
子研究动态装配之前，只投影授权会漏报或误报。选择**请求消费者前最后那份实际菜单**，
而非重算一套权限清单；每次快照对应当前步，不能用注册表或旧 run 补猜。
通用到插件/工作流/权限界面：定义、授权、装配、尝试、成功、服务健康是不同事实，
观察到前一个不能把后一个写成真。生产者/消费者同源还要验送达 UI 的脱敏出口。

承重测试也不能躲进错误处理：故障桩内的 AssertionError 可能被生产代码宽泛捕获，
再被测试期待的「服务不可用」状态吞掉。先在桩里捕获请求时的事件与输入，
**退出被测运行器后再断言**。本次删掉菜单落账，装配/未装配两种场景都红；
放宽公开句语法，私有名称与重复标签反例红。以上已固化成项目回归，非只有提醒。

### 修复续轮也必须保存义务与失败原因（2026-09-16）

finance `fix/e2-material-closeout@1e4cc6b6`：上层已准许无编号材料题零工具补写，
下层可满足性裁决却仍只认编号题，进入真实 runtime 后把 `direct_answer` 从修复指令删除。
回调替身直接返回好答案会漏检；回归须让原运行器实际续轮，并在退出后核对模型收到的义务。
同一冻结范围的可交付集合现在由上层准入、下层降级和题号解析共用。

另一方向同样危险：终止协议因来源/哈希完整性错误清空正文，外层只见缺格，便重新授予补写。
保留结构化拒绝码并复用原分类，不能凭空正文猜失败原因；未知来源拒绝不能变成普通漏答。
两种路径均已进入真实 runtime 的离线回归，模型/判官仍是替身，不能外推真实答题质量。
该形状也适用于支付重试、权限恢复和任务补偿：重试不能丢失原义务，也不能抹掉不可重试原因。

### 判官的理由也是待核验声明（2026-09-16）

finance E2 材料轮出现两层假支持：先是判官说“本句有材料锚点”，实际该句锚点列表为空；
加入可检查的支持类型和锚点序号后，又把无自身输入的计算复述标成 nonfactual，理由借了邻句。
逐句布尔值和长理由提高可审计性，但没有自动消除同源模型的盲区。

可机械认证的部分应落成凭据：覆盖的 claim ID、支持类型、仅指向本句的有效锚点序号、
拒绝单调收窄、缺失或矛盾不可通过。不可机械认证的部分须单列：事实/非事实分类、
计算是否由这些输入推出、删句后是否还回答了问题。不能把前一层绿当后一层的证明。
固定作者的正负对照与自然作者的新会话必须分开记；前者通过，后者仍可反证。

同样适用于审批理由、权限解释、自动代码审查：**解释提及了证据，不等于执行时真有该证据**。
候选实现与全部失败见 finance `docs/handoffs/2026-09-16-e2-claim-rendering-and-judge-receipts.md`；
诊断脚本只测真实判官，不代签端到端验收。回执记录用原生协议对象的 `to_dict()`，
不要用通用深拷贝跨过冻结映射；测试必须包含原生工具返回对象，而不只注入字典回调。

### 删除错误后，既要保住可信结果，也要重新检查任务完整性（2026-09-18）

finance `fix/8792-boundary-integration@9655b16d` 的两个实测形状：一次非法 URL 被正确拒绝，
失败记账却对只读 Mapping 做 JSON 序列化而抛错；另一答案删掉无依据阈值后仍有清单标题与日期，
因此被误标完整，后续缺口段还被登记成观察项。安全动作正确，不代表整轮交付已经正确。

可迁移规则：**内容有效性、任务完整性、持久化授权是三道独立检查。** 删除坏断言后保留
已核验邻句，再检查用户要的元素是否还齐全；同一预算内修复并复验，不能补则公开缺口。
补全异常只能恢复同一任务里此前已核验的稿，不能让新候选借用旧凭据。无可信前稿、身份不符
或完整性拒绝仍不得恢复；所有恢复路径继续走统一公开出口。这也适用于表单校验、批量任务
与渐进式计算：局部失败不应撤销已确认的部分，更不能升级未经确认的新部分。

该结论由原输入机械重放、真实 verifier/adapter 配假答复的组合、单项撤保护反证支持；
不是新真实模型效果验收。旧四题失败保持原判，金融质量与自然修复能力尚未签收。

同日另一真实样本（finance研究保稿35ee8a5c，GLM三轮）把同一形状扩展到结构化历史查询：
模型漏结束日期，注册表正确拒绝，却在进展记账JSON只读Mapping时整轮崩溃。
原件经真实parser→拒绝结果消费者重放，旧版复现stack，已有修复版返回原错误且44条证据不变。
**不要为恢复流程放宽输入校验；让错误能被反馈，保留已完成部分，模型才有原预算内自修的机会。**
失败汇总的used=false/tool_calls=0还可能掩盖此前真实消费，须对账持久事件而非把缺计数当零。
该对照仅是局部确定性检查，无自然续修/终稿证明；新旧live都未通过。量具在金融仓
`scripts/review_probes/replay_history_progress_failure.py`，原件见09-18 `finish-candidate-glm-live`交接。

### 校验意见、最终正文、实际副作用要分开对账（2026-09-18）

后续固定修复版四题真入口复验：运行状态全 completed，但一题只是错误澄清；另一题删除
列表里的无依据阈值，表格中的同义条件却仍公开；授权题真写了一个事项，完整性提示却把
“已登记”尾句当成另一条缺件。完整任务仍未过，不能拿前述工程证据倒签自然效果。

可迁移检查是三向对账：**校验器判了什么、用户实际看见什么、系统实际写了什么**。
同一断言变成表格/区分变量/尾注后仍要受约束；局部放行与整体完整性可以不同，但提示必须
说明真实缺什么。只看删句清单或状态码，会漏掉跨表达和跨出口的不一致。

成功也有层次：本轮10条计算失败反馈放在 ok=true 工具封装内，模型确实见到错误并续行；
只数外层 error 会漏故障。反过来，判官称“无依据/内部标识”也要回查：未绑定但存在的片段、
工具要求展示却被判官禁止的产物编号，都不能直接定成幻觉或密钥泄漏。审判官理由同样审合同。
这些原则适用于表单导入、审批、支付回执；场景量具在 finance 的
`scripts/review_probes/inspect_boundary_retest.py`，它是只读诊断，不是已修复的回归门。

### 表达变化不能改变义务，字段角色先于出现顺序（2026-09-18）

后续离线返修finance `97ca716b`：同一无依据阈值换成标题、表格、区分变量，仍需经过
原支持门；“已登记”是副作用回执，不是新事项；报告期、披露截止和个人复查日不能按
第一个日期竞争同一due。材料指代同理：必须绑定到它之前的来源请求及提供者，不能
因为全题出现一次搜索动词就免掉所有缺失附件。

可迁移到自然语言表单、审批和工作流：**先识别对象的角色/归属，再检查取值；不要
拿词面共现代替关系。** 以等价表达成组测试，同组同时包含该拒绝和该保留的输入；
删除保护时须真实执行用例且出现行为断言失败，加载错误或0tests不算反证成功。
句法规则是有范围的工程合同，不冒充通用语言理解；工程全绿也不倒签旧自然样本。
本轮175新回归、16组撤保护均有收据，原真实四题失败保留，金融选期与支持性另验。

### 机器字段、模型文本、计算产物分别验（2026-09-18）

取数对象里有结构化指标，不代表下游模型看得见。一次财报修复先去掉占额度的表头，
却发现公开投影根本不传机器字段，模型只收到裸数字。应从同批规范指标生成带主体、
单位、期间的文本，再经过真实压缩/预算投影验一次；不能只断言内部对象存在。

计算又多一层：进程exit0、输入哈希链完整、文件已生成，分别只证明运行、输入身份、
落盘。模型仍可能抄数进脚本而不读输入，或把嵌套结果放进仅接标量的summary槽，
使展示与派生证据为空。最后正文也可能抄错一个小数。因此验收应对照**同批输入、
独立数学参考、规范化结果、公开产物、最终正文**，任何一层都不能借上一层的绿灯。
这适用于财务报表、实验报告、导出和工作流结果页；不是再加一轮模型就能代替。

本轮数据行额度/模型标签已有正式回归与撤保护反证；完整计算展示/正文一致性仍是
真实失败样本，不写成已修。记录在finance分支feat/research-data-readiness的
`docs/handoffs/2026-09-18-research-data-readiness.md`，未往生产换候选代码。

### 资源耗尽不取消交付义务，标题不证明产物（2026-09-18）

finance R5 的组合反例：修复预算耗尽后，旧「不可达降级」把财务必答槽改成可选，
于是同一缺口从 partial 变成 completed。正确做法是分开**执行许可**与**完成判据**：
没额度就不能再取数，但用户仍然要那份结果；允许复用已有证据，补不齐保留可信正文并
明确 partial。不能通过缩小必答集合来使完成率变好。此模式同样适用于批处理、审批与导出。

计算任务的 purpose 叫「净现比」，不证明输出里真的有净现比。应检查绑定产物的指标、
有限数值与依赖，而不是任务标题或调用成功；这些机械检查仍不证明公式和金融解释正确。
相同报告期的完全重复行可以去重，冲突版本却不能无依据挑一份；缺披露日期不等于没有报告。
快照自动全绑定也不证明正文逐期交付。**身份、可用性、内容、完整性必须分别对账。**

同一会话的成功计算可以在绑定闭包中立即复用；不能因尚未落盘报不存在，也不能改成
全局缓存跨用户继承。结构缺口修复发生在首次语义检查前，语义删句后的修复才要求再做
语义检查；测试要观察真实阶段，不能为凑调用次数改执行链。R5 dfd7b4ff 的回归与14组
撤保护仅证明这些工程合同，未新增自然模型验收，不改变之前真实样本的失败判决。

### 修复状态不能代替原断言复验（2026-09-18）

后续真实样本中，计算表的比值全对，正文却另写错累计差；有真实登记，也仍有错误的
比较口径。判官先识别「半年与全年不等长」，再因补证标 lifted，原句却没改。
因此 **repair/repaired/lifted 都是流程状态，不是原断言成立的证据**。复验要取修后
用户实际可见的同一断言，重新核期间、运算及语义；拿更多证据不能改变六个月的长度。

相同阈值从表格改写成「是否回到某值」仍是阈值；完整事项后接免责声明不是新事项。
检测要跟随事实角色而非句式或段落边界。该模式适用于数据报告、审批回执和导出：
产物、正文、实际副作用三个出口各自有合同，不能互相代签。finance R6原件保留，
未为通过样本改判据或关闭事实门；这是返修输入，不写成已修能力。

### 局部修复要送达错因、保留引用，并重验最后一次投影（2026-09-18）

finance `feat/research-data-readiness@a31b572f` 把旧失败原件放进真实运行器后，又暴露两条
接缝：修复请求有缺件槽位却无具体错因；可信句及编号还在，所属槽降为缺口时引用卡被整批删掉。
修复不是再加预算或放宽完成判据，而是让**同一会话的原修复请求携带具体错因**，并从原先
成功、未被撤销的绑定中保留仍被正文引用的卡。保卡不表示槽位重新完整；无绑定、此前拒绝、
最终文本已去掉的编号都不能复活。日历/缺口提示等后续投影也属于交付面，必须再核最终文本。

另一组边界是时间：工具阶段关闭、总交付期限到期、修复额度耗尽分别验。若首次核验前总期限
就到期，未核验首稿不是可保留的可信稿；发现问题也不自动授予新权限或资源。对错误数字只
标待核对，不静默替模型写成正确数；无额度则保已核实部分并明确缺口。可迁移到报表、批量导入、
审批补正：**检测结果、续修许可、可信内容、完整性、最终呈现是不同状态**。

本轮结果协议准入、局部检查、错因送达、引用保留与最终投影已固化为回归，13组拆保护真实
断言红、逐项还原绿；默认旧变异套件另复验以免量具升级破坏原入口。脚本SDK/注入判官及
冻结输入重放只是工程证据，未新跑自然模型，原真实失败保持未通过。更广语义、来源归属、
公式和任意脚本实际消费输入仍另验；不是一组正则变成了通用判官。

**2026-09-19 独立合流反例**：`q/research-data-readiness@d12bd0b1` 的已有全量绿仍漏了一种
连坐：同一可信事实＋错误推断，用句号/分号分隔能保留前者，换逗号就连正文与引用一并删掉。
检测时已细分尾部语气，删除时却用了整句坐标；私有证据尚存不证明公开内容被保留。
可迁移规则：**定位错误的粒度必须约束修改粒度，拒错与保真要成对验**。用仅改标点的等价输入
驱动真实出口，同时断言坏内容消失、独立好内容及其引用仍在，适用于脱敏、审稿、修复与摘要。
量具已落金融 `scripts/review_probes/check_delivery_fact_retention.py`：关判官/成功替身两模式
6例4P/2F、exit1；这是阻塞修复的反例，不是已经补好的保护，不替自然模型质量签字。

## 修的时候两条纪律

- **成对改**：既改行为也改声明。只做规范化不声明 = 静默输入转换
  （ai-agent-book ch4 点名的反模式：Cursor 静默转换弯引号，模型反复失败且
  无法自行诊断）。
- **别每次都说**：没降级时返回空串。每次都挂一句「本次正常」会训练模型忽略
  这一行，比不说更糟——与「没依据宁可留空」同一条纪律。

## 为什么它架构性易发（可迁移的解释）

这五处都在**跨层边界**上：schema↔runner、prepare↔batch、provider↔observation、
orchestrator↔prompt、rag↔tool。每一层单独看都是对的——
**遥测层如实记了、执行层如实做了**，错在**没人负责把上层的事实搬到下层去**。

> 与已确立的「授予的额度必须真的传到最下游执行者」是同构问题：
> 只写进结构体不生效，比不做更危险（仪表全绿、实际没人管）。

所以设计跨层接口时，**默认假设是「上层知道的，下层不知道」**，
要显式搬运；而不是假设「反正都在一个进程里」。
