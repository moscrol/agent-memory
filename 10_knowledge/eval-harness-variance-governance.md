# 评测台方差治理：先确定性判据，后语义判官

LLM 评测台自己也会飘。单次运行读不出「这一刀有没有用」时，先别急着加重复次数
或上 LLM 判官——**先定位方差落在哪一层判据上**，多数情况下能用确定性手段消掉。

## 结论 / 要点

### 1. 方差要用「干净对照」测，不能跨修复比

只比较**输入相同且被测代码相同**的两次运行。跨越了一次修复的两次运行，测到的是
「修复效果 + 噪声」的混合，两个都读不出来。

判断是否干净的实操：逐对列出相邻两次运行之间改了什么。**server 侧代码改了但没重启
进程，这一对仍然是干净的**（Python 在 import 时装载）；判官/CLI 侧的改动不影响
被测答案，也是干净的。

实测教训：三次运行看上去 29% 规则级翻转，隔离出真正干净的那一对后是 7%，
而且翻转全在措辞层、数值层 0/20。用错配对会得出「事实层也不稳」的结论，
把修复指向最贵的那条路。

### 2. 方差按判据类型差一个数量级

同输入复跑实测（10 题 45 条确定性规则）：

| 判据类型 | 翻转率 |
|---|---|
| 数值型断言（带容差） | **0%** |
| 措辞型断言（要求正文出现某个词） | **67%** |
| 实体/引用/集合/时间 | 0% |

**推论**：把所有断言合成一个「通过/失败」会把两个数量级压成一个数，看板必然读不出
结论。看板至少要按判据层分账。

### 3. 「事实层稳」只在正确性上成立，别和「是否提及」混为一谈

模型很少把数字**说错**，但经常整个换答案形状、**根本不提**。判官若把「说错」和
「没说」记成同一种红，就丢掉了最重要的区分。

### 4. 确定性手段优先，LLM 判官只吃残差

四种修法的量纲对比（措辞类断言共 8 条的场景）：

| 修法 | 配额 | 是否消除方差 |
|---|---|---|
| 每题重复 n≥3 取多数 | 题数×3，通常超滚动上限 | ❌ 只测量不消除 |
| 看板标注「单次不可比」 | 0 | ❌ |
| 措辞断言改 LLM 语义判定 | 每次重渲都烧 | ⚠️ **在产品方差上叠加判官方差**；要量化判官方差就得重复运行，绕回第一条 |
| **确定性等价类 + 蕴含声明** | **0** | ✅ |

这在 RAG / Agent 评测里通用：**能用 exact match、正则、结构化字段判的绝不上
LLM-as-judge**。判官自身的方差会污染你要测的信号，而量化判官方差需要重复调用，
成本直接翻倍。确定性手段做完后，语义判官的目标面通常缩小一个数量级，再决定要不要上。

### 5. 每条断言必须绑定结构化锚点

这是消方差的统一原则，不是「放宽判据」：

- **冗余断言 → 声明蕴含**：若一条更严的规则（如带容差的数值断言）已经证明了同一事实，
  措辞断言零信息量。用声明式的「X 被规则 Y 蕴含」解除，**Y 没过时 X 原样生效**。
- **同义改写 → 等价类**：等价类必须**含正典短语本身**（否则一个笔误就整条换掉原断言，
  看板上看不出来），且**不得跨枚举值**。
- **枚举/字面量缺席 → 判失败，不判不可判**：字面量不在全文里就是真不在，
  不存在「定位不到」。（数值不同：光有个数字证明不了它绑在这个字段上，
  别名未命中仍应判不可判。）
- **语义标记 → 锚定操作数**：「答案里出现『矛盾』」不等于「指出了**这个**矛盾」。
  要求矛盾的两端也在场，否则纯关键词命中会产生**假绿**。

### 6. 等价类的纪律：先定义再验证

等价类必须**从数据模型或验收规则已有的措辞里取**，不能事后看答案补词——
那是过拟合到某次运行。判断标准：这条改动是让**同一事实的另一种合法表达**被接受，
还是让**另一件事**被接受。

配套信号：修完之后**题级通过/失败数不应该变**。变了就说明动的是门槛不是稳定性。

### 7. 中文特有的坑：修饰语在名词前

把数字绑定到字段名的「别名窗口」必须**对称**。中文「21949.97 亿元的成交额」
数字在别名前 13 字，只往回看 8 字就会把答对的判成答错。

配套的量纲验证方法：扫描窗口宽度对命中数的影响。若从「略微放宽」到「完全不设窗口」
命中数不再增加，说明窗口机制本身没问题，只有那一处不对称是缺陷——
**这个扫描同时证明了放宽不会引入假绿**。

## 背景 / 依据

- 实测报告：`finance-workspace-private/docs/verification/2026-08-01-acceptance-harness-noise.md`
- 效果：噪声 7% → 2%，数值层与语义标记层归零；题级通过/失败数不变（改的是稳定性与归因）。
- 前提约束：正典题库被 sha256 密封冻结，判据表达力只能走 additive overlay ——
  **这是好设计**，它逼着「放宽判据」这类改动必须显式、可审计。

## 验证方法学的坑

突变验证（改坏代码确认测试变红）时，若突变是**同字节长度**的改动
（如 `PASS,` → `FAIL,`）且突变+还原在**同一秒内**完成，Python 的 `.pyc`
按 `(mtime, size)` 校验源文件会认为缓存有效，于是一直跑突变版字节码，
伪造出「新回归」。任何 mutate-run-restore 循环后先清 `__pycache__` 再信全量结果。
