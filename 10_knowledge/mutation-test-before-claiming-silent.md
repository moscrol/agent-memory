# 宣称「沉默」之前先做变异

> **失败形状**：把「检查没响」当成「没问题」——测试没红、门禁没拦、判分器没扣分、
> 改动后行为「没变」。沉默有两种来源：确实没问题，或**检查根本没在看**。
> 不做变异（故意改坏、确认它会红），两种沉默长得一模一样。

术语见 [[../30_conventions/glossary]]：变异验证 = 故意改坏被测逻辑，确认检查/测试真的会红——防「永远绿的测试」。
本条讲的是**什么时候必须做**、以及变异本身怎么做假。

## 什么时候必须先变异再下结论

| 你要说的话 | 先做的变异 |
|---|---|
| 「这条测试覆盖了它」 | 把被测行为改坏，测试要红，**并且红在这条** |
| 「门禁上岗了」 | 造一条违规，门禁要拦**并指名哪一条**；带理由的豁免放行、不带理由的仍拦（四项，缺一不可，见 [[evidence-hygiene-three-failure-shapes]]） |
| 「判分器 / 分类器读数可信」 | 把真值打乱，分数要掉；把系统改成「永不触发」，相关计数要归零 |
| 「这次重构是纯等价 / no-op」 | 反向变异：底座忽略领域申请要红，领域回焊底座也要红（双向） |
| 「改了标签就是改了行为」 | 把**真实产出值**喂进消费者、打印结果；不要读代码推断走哪个分支 |

## 实例（都实际发生过）

- **08-12「测的是空气」**：变异用的替换串带了引号前缀、没匹配上，是个 no-op；「测试没红」被当成结论。
  纪律：替换后先 `assert old in s` 再 `assert new != old`，然后才跑测试。同族：变异改出来的字符串
  仍是断言的子串（「方括号包起来」改成「方括号」），测试照样绿——**变异要删整句，不要改一半**。
- **08-27 抽数正则**：`\d{1,3}(?:,\d{3})*|\d+` 这种「千分位在前」的有序交替，在 `26531.66` 上先吃掉
  `265` 就宣告成功，真值永远匹配不上，D1 被判 0.429（修后 0.714 / 打乱 0.286）。读代码看不出来，
  变异抓的。**判分器自身必须先过变异再上岗**，否则所有分数作废。
- **08-27 判官修复第一版是死代码**：改了 `_failure_reason` 保留异常种类，但下游读的是另一个串，
  异常正文根本不进去——生产路径一行行为都没变，而拼串自测的测试跟着同一个误解一起绿。
  判据只有一条：**用真实产出值起判**。
- **08-31 rubric v2**：变异（同文本重复盲评）证伪了自己的第一版——一票否决塞进连续分，方差反而变大，
  见 [[veto-inside-a-continuous-score]]。
- **09-03 `audit_tool_reachability.py` 初版恒真**：实测 0.2s，「快是因为它什么也没验」；
  同日 `audit_dataset_registration.py` 的判据若取自被审计的注册表本身，「没注册的表」按定义是空集，
  门禁恒真。**门禁上岗前自己先过变异**，且判据要独立于被审计物。
- **参照系自己的门禁**：harness-reference `verify_sources.py`（追加一字节 → exit 1）、
  `check_refs.py`（路径改坏 → exit 1，行数改坏 → 报漂移）都是先变异再登记。

## 变异本身怎么做假（量具陷阱）

1. **先清 `__pycache__`**：同字节长度突变 + 同秒内还原，`.pyc` 按 `(mtime, size)` 判缓存有效，
   会伪造出「新回归」——红也可能是假的。
2. **变异必须真的落盘**（见 08-12 实例）。
3. **量具必须覆盖被改的那一步**：消融壳走 legacy 管线，改 episode 链的刀在它上面读不到；
   变异改在量具看不见的地方，永远绿。
4. 变异恢复不用 `git checkout --`（会连别人的在途改动一起冲掉）；用备份文件或精确逆替换。
5. **别用「整份回退到修复前」当变异**（2026-09-21 finance `hithink_client` 实测）。
   新测试几乎总会引用新符号（常量、关键字参数、helper），把整个文件换回旧版后，
   9 条新测试**全红在 `module has no attribute 'ENV_RATE_LIMIT_BUDGET'`**——红在
   helper 的一行，被测行为一次都没执行到。**全红此时等于零信息**，而它看起来像最强的证据。
   做法：保留新符号，每次只破坏**一个行为点**（触发判据 / 解析器 / 边界），
   要求它**恰好**红掉对应那一层、邻层保持绿；那个划分本身才是证据。
   同轮三次定点变异分别红 6 / 3 / 3 条，互不重叠，另外意外查出「拿掉预算检查后是
   `OverflowError` 而非挂死」——**说明预算检查是那个重试循环唯一的界**。
   推论：变异不只验测试，也在给实现测边界。
6. **比较修前修后，必须使用同一个变异**。例如“取最后一项”和“取最后一条非空”并非同一种错误：后者额外破坏等待空消息的合同。2026-09-13 探针复审实测，前者旧7例全绿→新1红，后者旧2红→新3红；混成“旧全绿→新3红”会夸大新增测试的保障。分别保存变异代码、失败用例ID和前后输出，变异运行禁写普通通过收据。

7. **协调钩子不能兼任语义证人**（2026-09-23 runtime writer）。测试先等内部锁钩子、再看close是否等待消息；撤掉锁后钩子根本不来，测试虽红，却没观察close提前返回。应直接观察合同动作（例如阻塞中的close不能完成、竞争者仍Busy），同步手段要独立于被撤保护。具名测试红仍不足够，还要看红在了哪个断言。
8. **不能只按异常类型判真伪**。收集/import错误当然不能算，但变异删掉必需输出字段后，真实消费者的精确KeyError可以是语义证人。接纳必须绑定“变异id + 完整参数化用例名 + 精确字段消息”，并有无关KeyError拒收自测，不能泛化成“所有异常都算kill”。修校验器后对旧输出重新裁决，应保留原拒收和输出hash，注明不是重新执行测试。工具实现见finance PR #884的 `scripts/review_probes/run_runtime_contract_checks.py`。

9. **隔离环境也要先证明会拒绝**（2026-09-23 PR884本机门禁）。macOS策略虽有`deny network*`，把local/remote过滤器放进同一条`allow network*`后，外连仍实际成功。先读配置就开测，等测到一半才预检，导致整轮不能作为隔离验收。修复为分别授权network-inbound/local与network-outbound/remote，并在副作用前动态检查本机连接成功、远端连接明确PermissionError、security CLI拒绝执行。超时/不可达不能冒充策略拒绝；坏策略要被预检拒收，正确策略要通过。工具已归finance `scripts/review_probes/check_loopback_sandbox.py`；范围仅IPv4 TCP及该CLI，不据此宣称完整主机或所有钥匙串API隔离。原始错误收据保留，另起固定提交和新目录复验。

10. **额外隔离也可能破坏被测前提**（同轮PR884）。特定外层Seatbelt策略让沙箱自测及RSS读取7例重复变红；相同8例在正常主机环境8P，再套该策略7F/1P。第8例清理脚本超时未稳定复现，不能把8红全归一个原因；也不能泛化为“macOS完全不支持嵌套沙箱”，allow-default两层冒烟是绿的。应保留原红、做同例环境对照，再按适合该叶子的环境**重新跑完整门禁**。去掉宿主额外限制不等于关闭测试自身的防护，但必须如实声明没有整轮OS级禁网。环境分类之后仍不可把局部复跑加到原全量数字里。

11. **硬截止后的无输出是UNKNOWN，不是零失败**（2026-09-23 PR884新候选2bc799a8）。完整pytest在1800秒被终止，`run_main_gate.sh`管道末尾的`tail -15`尚未给出pytest终局输出，JUnit与最终收据也不存在；只能确认前置Ruff通过，不能说“除了超时全绿”。长跑应先流式保存原始输出，再截尾展示；缺少终局收据时仍须判incomplete，不以已知局部或旧候选补齐。每个agent只跑一个全量，也不等于整机有容量：同机仍可有其他全量并发。并发与磁盘下降是观察事实，未做对照就不能冒充唯一根因。失败现场保留，并将即时清理快照与稍后进程复查分开记录。

12. **错误文案变化不等于目标保护被验证**（2026-09-23 PR884第04轮）。撤掉证据快照摘要校验后，篡改仍被展示一致性校验拒绝，只是`raises(match="digest")`变红，不能据此宣称坏数据已穿透。把原始与展示标题一致地篡改、保留摘要不变，再撤摘要校验，才观察到坏数据被接受并触发DID NOT RAISE。原弱变异和强化后的反例分别留存，不倒改首红。

13. **复用与并发探针先固定对象和阶段**（同轮）。注释声称同实例异常后复用，代码却新建episode2，是另一条合同；等待模型在飞但只推进到model_pending，也是在错误阶段等事件。应保留原实例，明确推进到副作用前步点，再用独立事件确认请求已在飞。setup错误后可复用不自动证明所有在飞异常的清理。

14. **模型CLI零退出不等于模型成功交卷**（同轮）。K3第18请求收到HTTP504，CLI仍exit0且没有终稿；控制器依据模型error事件和缺失报告拒收，没有重试或用宿主补验追认。核验应同时绑定模型身份、输入hash、请求台账、有效终稿和原始动态证据；单看进程退出码或报告里的PASS均不够。参见finance `docs/handoffs/2026-09-23-pr884-closeout-04.md`。

15. **惰性对象创建不等于目标阶段已到达**（2026-09-24 finance #868）。包装器返回 `@contextmanager` 对象时尚未打开 HTTP；在返回后启动取消 timer，仍可能只取消启动而非阻塞读取。第一次把 sleep 放在创建前，测试绿却未覆盖真正进入阶段。把延迟放进 `__enter__` 前，旧探针三路径都红；进入真实响应后才计时，正常/撤转发/恢复三组才分别通过/拒收/通过。事件名也不能由包装器自行命名后就当证据。另一个独审慢流夹具声明 Content-Length=12 却发100字节，且按行迭代却不发换行；原件和只修长度均失败，长度与换行都修正才通过。宿主对照支持夹具诊断，不代独审改判。正式回归在金融 `c315cfdaa`；原始对照在 `pr868-merge-ready-20260924-0135/reviewer-framing/`，不是自然金融验收。

16. **探针新增拒绝条件后，要追到最终准入者**（同轮）。严格探针已将“未触及目标阶段”写入 coverage_gaps 并退出非零，生成的活体验收启动器却只读 deadline_violations，存在漏接。本轮外层拒绝阻止了实际提交，但不能据此宣称所有入口已闭合。修复让正式入口重算场景覆盖/时限、校验完整集合与当前干净候选身份，并在起侧车前执行。撤掉判据为5条具名断言失败，撤掉入口调用为1条接线断言失败，恢复25P；两层分开验证。实现仍是领域准入函数与正式回归，不将绑定本批路径的控制脚本包装成通用框架；完整门禁和独审另签。

17. **截尾可以是展示策略，不能是持久化策略**（2026-09-24 finance #868）。完整工程有7个RAG失败，却只留下`pytest | tail -15`的失败ID，原堆栈无法恢复；局部绿和另一个前缀覆盖红均不能解释它。修复将完整输出写进本轮唯一收据目录，再截尾展示，同时检查tee/tail退出码和日志存在性。收据落在显式basetemp内也必须拒绝，否则绿后清理会连证据一起删除。旧日志/管道反例4F、位置反例2F，修复后相关72P；实现为finance e7a6cb412的`run_main_gate.sh`与`test_main_gate_receipt.py`。这是证据链修复，不是原7F根因修复；旧失败保留，新候选完整工程另签。

18. **HTTP成功不等于结构化交付成功，避免JSON套字符串**（2026-09-24 finance #868）。独审Quality的14个上游响应均200，执行阶段最后的工具参数却把整份结果二次编码进字符串，内部括号错误使控制器exit75且无最终报告。宿主不修旧JSON补签；另建对象型工具参数与绑定器原型，旧坏字符串仍拒绝，新合成对象在注册工具边界通过，身份伪造/超限/错误类型仍拒绝，15项离线对照且原请求SHA不变。原型没有真实provider验证，也未安装进封存批。只有21请求余额时，不因单阶段尚能起跑就启动无法按既定双轴配额完成的半轮；总账、阶段状态、有效verdict和覆盖分别检查。源码与收据保全在finance `docs/verification/2026-09-24-adaptive-e7-qc-closeout/`，不是新的通用执行入口。

## 与「信息没送到」的关系

[[info-not-delivered-bug-pattern]] 是「存在 ≠ 送达」；本条是「没响 ≠ 没事」。
两者常一起出现：字段记了没传（没送到），而覆盖率审计 grep 到字段就发绿（没响）——
先变异（把字段删掉，审计该红却不红）就同时暴露两件事。
