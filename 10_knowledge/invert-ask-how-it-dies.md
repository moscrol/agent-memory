# 反过来想

## 判据

**不要问"怎么才能成功"，问"最可能怎么死"，然后检查自己是不是正在往那儿走。**

这是一条**提问替换规则**，不是"要注意风险"的同义词。

## 它不是"列风险清单"

| | 风险清单 | invert |
|---|---|---|
| 方向 | 从外部坏事出发（对手、政策、资金链） | 从**自己当前的行为**出发 |
| 产出 | 一份要提防的东西 | **一条你正走在上面的路** |
| 谁能写 | 不了解你的人也能写 | 只有知道你这周在做什么的人能写 |

风险清单里写"竞争加剧"是安全的废话。invert 要求写的是：**按我现在的做法，最可能的结局是什么。**

## 怎么用（三步）

1. **写出最多三条死法**，每条必须是**你的行为能改变的**（"行业消失"不算，那是焦虑不是判据）
2. 给每条标一个字段：**当期有痛感 / 当期无痛**
3. **只对"无痛"那条设外部触发器**——一个日期 + 一个读数

### 第 2 步是这条判据的全部价值所在

**有痛感的死法自带报警**：现金见底、客户投诉、CI 全红。它们不需要你记着，它们会来找你。

**无痛的死法没有报警**，而且伪装成勤奋——每天都在进步、每天都很充实、每天都有可见产出。**你不会在任何一天感觉不对。** 等痛感出现时，已经过去三年。

所以：**有痛的那栏不用管，管无痛的那栏。** 超过三条就退化成风险清单了。

## 适用条件

- 定方向、排优先级、决定"接下来三个月投哪儿"时
- **尤其在一切看起来都在顺利推进的时候**——那正是无痛死法的生长期

## 什么时候我不用它

- **痛感已经出现、人已经在死亡路径上** → 此时要的是止损动作，不是再分析一遍
- 死法不可控 → 写了不产生行动
- 用它替代执行 —— 每周想一次和每天想一次的信息量一样，多出来的只有焦虑
- 决策可逆且成本低 → 直接试比想便宜

## 与项目的关系（推测）

对 [[foresight]]，三步走完是这样：

| 死法 | 可控？ | 当期痛感 |
|---|---|---|
| 三年后系统很完美，但从未有人付钱 | **是**（现在就能改） | **当期完全无痛** |
| 钱烧完 | 是 | 有痛感——不用管，会自己报警 |
| 技术做不出来 | 是 | 有痛感——build 会红 |

**只有第一条需要触发器。** 它的证据在 `foresight/docs/offer.yaml`：`status: draft`，三个渠道分别是 `not_open` / `to_test` / `not_open`——**没有任何一个对外口子是开的**（[实测] 2026-09-14）。

触发器的形状是「日期 + 读数」，例如：*到某日仍无一笔真实付费收入，则停止新建系统功能，时间全部转到人力版。* 具体日期和阈值由本人定——**判据只负责指出这一条必须有触发器，因为它是唯一不会自己提醒你的那条。**

配套：[[one-foot-hurdles-not-seven]] 说的是**怎么避开**这条死法（先跑一英尺的人力版）；本条说的是**怎么发现自己正在上面**。
