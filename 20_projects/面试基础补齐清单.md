## 0. 用法（重要，别当教科书目录读）

每一项先看**自测题**。能用自己的话讲清楚就划掉，不用学；讲不清楚再往下看
「你项目里的对应物」，**从自己写过的代码倒推知识点，不要从零看教程**。

这条捷径是你独有的：别人背定义，你能答「我踩过一次 X，后来改成 Y」。
同一个知识点，有伤疤的版本考官记得住。

**标注约定**：`[P0]` 必补，答不上很难看 · `[P1]` 看投什么岗 · `[P2]` 可延后。

## 1. 数据库 `[P0]`

**为什么考**：你简历上写了 49 表星型 schema、VIEW、generation 表、快照 id 进主键，
面试官一定会顺着问原理。这是你最容易答得漂亮、也最容易翻车的一块。

| 自测题 | 你项目里的对应物 |
|---|---|
| 事务的 ACID 各指什么？隔离级别有哪几种，各自防住了什么异常？ | 文件事务 `pending / committed / rolled_back` |
| 为什么要读写分离？读方只查 VIEW、写方写 generation 表解决了什么？ | 板块日行情的蓝绿写入 |
| 主键、唯一索引、联合索引的区别？为什么快照 id 要进主键？ | 快照分代表设计 |
| 索引为什么能加速查询？B+ 树凭什么比二叉树适合磁盘？ | DuckDB 星型 schema |
| 什么是脏读、不可重复读、幻读？MVCC 怎么绕开加锁？ | —— |
| 星型 schema 和雪花模型的取舍？为什么 OLAP 用列存？ | 49 表星型 schema、DuckDB 本身就是列存 |

**踩过的坑可直接当答案**：「行数审计全绿、值全 NULL」的空壳写入事故 → 讲
「完整性约束不能只看行数」；换板块名单污染历史口径 → 讲「维度缓慢变化 SCD」。

## 6. Python 工程能力 `[P0，但按现状自评]`

**为什么单列**：你是 AI 辅助开发者。面试官心里第一个问号是
「这 4.5 万行是不是 AI 写的」。**这一项的目标不是学新语法，是获得「现场能改」的能力。**

- [ ] 不看 AI，能读懂自己仓里任意一个函数并说出它的输入输出与异常分支
- [ ] 能当场给一个已有函数补一条单元测试（pytest）
- [ ] 能解释项目里的装饰器、上下文管理器、dataclass、Protocol 各在干什么
- [ ] 能手写：文件读写、`dict`/`set` 操作、列表推导、异常处理、简单类
- [ ] 看得懂 traceback 并定位到自己代码的哪一行
- [ ] 知道虚拟环境、依赖锁定、`ruff` 在管什么

**验收方式**：随便挑一个自己写过的模块，关掉 AI，给它加一个小功能 + 一条测试。
做得到就过了；做不到，缺口就在这里，不在「全栈」。

## 7. 不建议现在投入的 `[P2]`

- **系统学一遍「全栈」**：数据层 / 后端 / 前端 / 部署你都写过了，缺的是命名和证明，不是能力。
- **K8s、Kafka、大数据栈**：等攒够十来份目标岗 JD，看哪个词反复出现而你确实没有，那才是缺口。
- **刷大量算法题**：除非确定投会考的公司。
- **补 Transformer 训练/推理理论**：已在 `70_tutor` 的 V3 手册里排成 P1，按那条线走，别在这里重开。

## 8. 建议顺序

1. 先做 **§6 的验收**（关掉 AI 改一个自己的模块）——这一条决定后面怎么排。
2. **§1 数据库** → **§2 并发**：这两块你项目里证据最多，性价比最高。
3. **§4 操作系统** → **§3 网络**：你有实操经验，只是缺术语对齐。
4. **§5 数据结构**：只做和检索相关的那五条。
5. 回 `20_projects/金融Agent面试学习.md` 继续领域轴。
