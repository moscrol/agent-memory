# 创业商业信息车道（修订）

## 结论（先看这）

**不需要**再创建一个「创业 FinHot」或再建一长串关注账号。

你 X 里已经关注了人。真正缺的是：**同一条时间线上的内容分类 + 门槛**，而不是「再抓一遍」。

```text
已关注账号的帖子
    ↓
车道分类（finance | venture | noise | ignore）
    ↓
分车道打分 / 门槛
    ↓
金融轨 → 投研 / KB
创业轨 → agent-memory inbox → 创业顾问（可选）
噪音 → 沉底不进晨报
```

## 不要做什么

- 不要为创业轨复制一整份 `watchlist.json`（和金融关注重叠、还一股脑抓）
- 不要新开一个 Grok Bot 专门刷 X（Bot 不是爬虫；采集仍归 FinHot / 本机管线）
- 不要把「关注了」当成「每条都值得入库」

## 要做什么（最小产品）

1. **条目级标签** `lane`: `finance` | `venture` | `noise`  
   - 规则 + 轻量模型均可；先规则词表，再校准  
   - 同一作者可以发金融帖也可以发创业帖 → 必须按**帖**分，不能按**人**分死
2. **分车道门槛**（示例）  
   - finance：沿用现有 qualityScore / 披露敏感度  
   - venture：偏「可复用经营判据 / GTM 可验证 / 一人公司实务」；喊单、情绪、纯涨跌叙述降权为 noise
3. **下游**  
   - venture 高分 → `agent-memory/00_inbox/`（knowledge-capture）  
   - 需要经营判断再 @创业顾问  
   - 可发素材再给内容运营（仍过门禁、不代发）

## 和草案旧版的关系

旧版里的「首批 X handle 清单」降级为**可选种子**——只在「你 X 关注里还没有、但想补采」时用。默认输入 = 你现有关注流 / FinHot 已采到的 X 条目。

## 下一步（派工）

- 产品改码（条目 lane 字段 + 过滤器）：用户本机 CLI 或明确派 **投研工头**（FinHot 属产品仓时）  
- 经营向词表 / 什么算好创业帖：可让 **创业顾问** 出一版判据草案（advisory，非决策）  
- OPC 工头：晨报只捞 `lane=venture` 且过门槛的条目，不整页倾倒
