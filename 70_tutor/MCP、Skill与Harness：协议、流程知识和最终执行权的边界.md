# MCP、Skill 与 Harness：协议、流程知识和最终执行权的边界

## 一句话先懂

`MCP`（Model Context Protocol，模型上下文协议）规定工具能力如何被标准化连接和调用；`Skill` 描述一类任务应该怎样完成；`LLM` 产生语义上的调用意图；`Harness`（Agent 运行时控制层）决定这个意图是否允许真正发生。**协议、流程知识和执行授权不是同一层。**

## 大白话解释

把 Agent 想成一家公司的工作系统：

- `MCP` 像统一插座标准：规定不同电器如何接入，不决定谁能通电。
- `Skill` 像岗位操作手册：告诉员工完成一类任务通常要先做什么、后做什么、缺什么时停下。
- `LLM` 像能读懂手册并提出下一步的员工：它能理解任务、选择动作、填写参数，但不能自己给自己发放权限。
- `Harness` 像门禁、审批、调度和审计系统：检查当前动作是否允许，执行失败如何恢复，结果如何回到工作上下文。

因此，Skill 里写着“运行清理脚本”，不等于脚本就能运行；LLM 生成了合法的工具调用，也不等于外部世界必须执行它。

## 第一性原理推导

1. 工具提供方和 Agent 客户端需要互操作；如果每个框架都有一套接入格式，同一个工具必须重复适配。
2. 所以需要一个协议，统一工具发现、描述、调用和返回的基本通信方式，这就是 MCP 的位置。
3. 但“能不能连接”不等于“这项任务应该怎样做”；任务流程、前置条件、失败边界和输出要求需要另一种知识载体，这就是 Skill。
4. LLM 只能根据当前 message 生成下一条响应，可能是文本、澄清、计划或结构化工具调用；它不直接拥有数据库、文件或外部 API 的执行权。
5. 外部动作存在权限、预算、幂等、审批、审计和恢复要求；这些不能只靠自然语言提示约束，必须由代码在执行边界上硬控制。

因此推出：

```text
MCP：能力如何互操作
→ Skill：任务通常如何组织
→ LLM：当前下一步想做什么
→ Harness：当前是否允许这样做
→ Tool：具体动作如何执行
```

## 技术映射

### MCP 的位置

MCP 更像 HTTP：它是协议规范，不是某一段神奇代码。典型交互可以抽象为：

```text
MCP Client → tools/list
MCP Server → 工具名称、描述、JSON Schema

MCP Client → tools/call
MCP Server → 执行工具并返回结果
```

实际系统通常需要：

```text
MCP Server：暴露工具、资源和提示模板
MCP Client / Adapter：把 MCP 接入具体 Agent 运行时
Harness：接管权限、预算、状态、重试、审计和结果验证
```

MCP 的原语可以先这样记：

| 原语 | 面向什么 | 人话解释 |
|---|---|---|
| Tool | 模型可执行的操作 | 模型可以做什么 |
| Resource | 应用可��取的数据 | 应用可以读什么 |
| Prompt | 可复用提示模板 | 用户或应用可以怎样开始任务 |

### Skill 的位置

Skill 不是权限清单，而是任务层的知识：

```text
任务目标
→ 前置条件
→ 工具组合与顺序
→ 失败边界
→ 输出要求
```

Skill 可以让 Agent 知道“应该运行什么”，但不能绕过 Harness 的授权判断。

### Harness 的控制点

Harness 不是只在开头和输出前检查一次，而是贯穿生命周期：

```text
接入前：来源、版本、所需权限
发现时：当前用户和任务能否看到该能力
调用前：Schema、权限、预算、审批、风险
执行中：超时、重试、取消、并发、状态
返回后：契约、日期、来源、空结果、提示注入
上下文注入：长度、脱敏、来源和时点
输出前：事实/推断边界、敏感信息、用户可见性
会话后：轨迹、审计和失败样本
```

### 优先级

```text
系统安全策略 / Harness 硬规则
    > 用户当前授权范围
    > Skill 工作流建议
    > LLM 当前调用意图
```

这不是说 Skill 没有价值，而是说流程建议不能自动升级为执行权。

## 术语对照

- `MCP（Model Context Protocol，模型上下文协议）`：统一模型客户端与工具/数据源之间发现、描述和调用方式的开放协议。
- `MCP Server`（MCP 服务端）：实现协议并暴露工具、资源或提示模板的一侧。
- `MCP Client`（MCP 客户端）：连接服务端、读取能力并发起调用的一侧。
- `Skill`（任务技能/流程知识）：描述一类任务的目标、步骤、前置条件、失败边界和输出要求。
- `Harness`（Agent 运行时控制层）：组织消息、调度 LLM 和工具，并执行权限、预算、状态、恢复与审计。
- `Adapter`（适配层）：把一种协议或接口转换成宿主运行时能管理的内部对象。
- `Tool Contract`（工具契约）：工具的输入、输出、错误、边界、副作用和权限约定。
- `Progressive Disclosure`（渐进式披露）：先给少量目录或摘要，需要时再加载完整定义和执行细节。
- `Authority`（执行权限）：允许系统真正改变外部状态的资格；它不等于模型给出的意见。

## 本轮场景对照

原书的“部署应用”例子可以这样理解：

```text
Skill：
  1. npm run build
  2. docker build
  3. kubectl apply

LLM：
  读懂流程，提出下一步命令或工具调用

Harness：
  检查当前工作区、权限、审批、预算、命令风险和执行结果

通用执行器 / Tool：
  具体运行命令并返回 stdout、stderr、退出状态
```

如果 Skill 写着“运行清理脚本”，但脚本会删除旧缓存、当前会话只有只读权限、用户没有批准、脚本也没有 dry-run，正确链路是：

```text
Skill 命中
→ LLM 提出运行意图
→ Harness 拒绝或要求审批/演练
→ 不执行删除
```

这不是 Harness 阻碍 Skill，而是把“流程知识”和“真实副作用”隔开。

## 替代方案与取舍

| 方案 | 优点 | 代价与风险 |
|---|---|---|
| 每个框架单独适配工具 | 早期简单直接 | 重复开发，生态无法复用 |
| 只用 MCP，不建 Skill | 接入统一 | 工具多时缺少任务流程和选择知识 |
| Skill 直接授予权限 | 路径短 | 被污染的文档或错误流程可越权 |
| 只靠 Prompt 写“不要危险操作” | 成本低 | 软约束，无法替代代码门禁 |
| MCP + Skill + Harness 分层 | 互操作、流程和授权分工清楚 | 需要维护注册表、策略和观测闭环 |

## 边界与反例

- **MCP 不是完整 Harness。** 它统一连接和调用形状，不自动提供业务授权、重试、上下文压缩或事件队列。
- **Skill 不是权限授权。** Skill 命中只说明可能相关，不说明当前用户可以执行其中的每一步。
- **LLM 不是最终执行者。** 它生成调用意图，工具执行和副作用必须经过 Harness。
- **只读不等于不需要权限。** 读取敏感文件、越权数据或恶意外部内容仍然需要范围和来源控制；只是低风险读取通常自动放行。
- **当前项目的路由实现不是原书规定。** 原书明确讨论 MCP、Skills、动态工具发现和工具生态挑战；具体的预处理、意图信封和规则快路径属于某个工程实现方案。
- **把所有安全检查推迟到输出前太晚。** 写库、删除、发送等副作用必须在执行前拦截。

## 可复用检查清单

- [ ] 我是在解决协议互操作、任务流程还是执行授权？
- [ ] Skill 是否清楚写出前置条件、失败边界和不适用场景？
- [ ] Skill 中的每一步是否仍经过 Harness 权限判断？
- [ ] 当前工具来源、版本和凭证范围是否可追溯？
- [ ] 调用前是否有 Schema、权限、预算和审批检查？
- [ ] 工具返回进入 LLM 前是否经过来源、时点、长度和提示注入治理？
- [ ] 输出前是否区分观察事实、推断、预测和执行权限？
- [ ] 是否有审计轨迹证明“谁在什么条件下允许了什么动作”？

## 自测题

一个 Skill 写着“发现数据缺口后运行 cleanup_missing_data.py”，该脚本会删除旧缓存并重建数据；当前 Harness 只有只读权限，用户没有明确批准，也没有 dry-run。系统应如何处理？

<details>
<summary>参考答案</summary>

Skill 只提供流程建议，LLM 可以理解并提出调用意图，但不能因为 Skill 命中就获得权限。Harness 应拒绝实际执行，或先要求用户确认并提供 dry-run；在没有批准、只读权限和可预览路径的条件下，不应发生删除副作用。原因是“建议执行”与“授权执行”属于不同层，副作用必须在发生前受独立代码门禁控制。

</details>

## 跨领域同构

- **网络协议与防火墙**：HTTP 规定请求如何表达，防火墙决定哪些请求可以通过；协议互通不等于访问授权。
- **企业 SOP 与门禁**：SOP 告诉员工按什么步骤办事，门禁和审批系统决定员工能否进入高风险区域。
- **编译器**：源代码表达意图，编译器和运行时检查类型、内存与权限；能写出语法正确的程序不等于系统允许它访问所有资源。

**面试挂钩**：回答 Agent 工具架构题时，可以按“协议互操作（MCP）→ 任务流程（Skill）→ 语义决策（LLM）→ 执行授权与恢复（Harness）”分层，最后补一句“Skill 和模型都不能自授予权限”。
